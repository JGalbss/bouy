# Migration and coverage plan

Status: partly superseded, 2026-10-16. After this plan was written, the owner decided that every npm package must run unchanged: "we need to be able to use all npm packages otherwise what is the point" ([the goal](../goal.md)). So the phases that reject or rewrite JavaScript constructs give way to ADR 0003. The usage data, the divergence detectors, and the diagnostics work stay useful. Nothing in this file is built. [The contract](beam-runtime.md) and [the diagnostics design](diagnostics.md) stay normative. This plan orders the work in six phases. Section 14 lists the changes that it makes to the diagnostics design, and each change lands in diagnostics.md when its work package starts.

## 1. Goal

The owner's direction, verbatim:

> deprecate and replace some ts concepts but like migration should be easy with an agent given good errors and shit to change to elsewhere

> effect ts should work

> hm ideally we like handle orprovide a path towards migrating codebase to this and all functionality covered and shit, also effect ts should work

Buoy keeps BEAM semantics. Every value is a copy, an actor is a process, and `await` blocks. Each TypeScript construct ends in one of two states:

1. It behaves as it behaves in Node.
2. `buoy check` rejects it with a stable code and the code to write instead. The replacement also runs on Node, so a team keeps its Node tests green until a module imports from `buoy`.

The path for a team, from the loop of diagnostics.md section 9:

1. Run `buoy check src --summary`. It counts the work for each code and puts the modules in an order.
2. Run `buoy fix src`. Each fix that it writes keeps Node behavior, so the Node tests still pass.
3. Give a coding agent the instruction text of diagnostics.md section 9. It fixes one module at a time, in plan order, with `buoy check` and `buoy explain`.
4. A module that needs an API that Buoy lacks waits. The `gaps` list of the report tells the Buoy team what to build next.
5. After the migration, the Claude Code hook of diagnostics.md section 9 keeps each edit inside the subset.

Effect works when a program that uses effect 4.0.5 compiles on Buoy and prints what Node prints. Phase 4 proves each part with an equivalence program against the real package.

## 2. The rule: no silent divergence

| Term                  | Meaning                                                                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| silent divergence     | The program compiles on Buoy, and then it prints or returns something different from Node. This is the worst outcome.                                |
| late rejection        | The program compiles, and at run time it throws a `TypeError` whose `code` is `"ERR_BUOY_UNSUPPORTED"`. The failure is loud, but it comes late.      |
| documented difference | A silent divergence that the contract lists, because no check catches it yet. Section 13 names the item that ends each one.                          |
| deprecated construct  | Valid TypeScript that Buoy rejects by design. Its diagnostic has the category `rejected` and names the replacement. Section 12 lists the constructs. |

The rules:

1. A feature lands with conformance programs whose output equals the output that Node recorded.
2. When Buoy cannot run a construct as Node runs it, the compiler rejects the construct. When the compiler cannot see the construct, because types are erased, the runtime throws a late rejection. Neither one may produce a wrong result.
3. Every fix that a diagnostic proposes keeps the behavior of the program on Node, except a fix that imports a Buoy construct such as `sleep` or `spawn` from `buoy`. So a false positive costs one edit, and it never adds a bug.
4. A feature that adds a new way for two names to hold one value lands after the check that guards it (decision D2).
5. Each documented difference has a program in `tests/divergence/`, and the list of open ones only shrinks.

The numbers that the team tracks:

| Number                                    | Where it comes from                                                                                  | Target             |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- | ------------------ |
| open silent divergences                   | the lines of `tests/divergence/open.txt`                                                             | 0                  |

Rules for every work package (WP):

- One agent owns one work package and changes only the files that it names. Two packages that name one file land in order.
- A package lands in one commit with its tests, its explain pages, and its change to the contract, and `pnpm check` passes.
- A package that adds a runtime function adds it to `GLOBAL_FUNCTIONS` or `EFFECT_NAMESPACES` in `crates/buoy-compiler/src/library.rs` in the same commit.
- Only `scripts/freeze-expectations.sh` writes `.stdout` files. No package edits `tests/migration/before/` or `tools/oxlint/guardrails/`.

Each item updates the contract and its register programs. The design notes below condense the TypeScript study.

**3.1 Key order and JSON hooks.** Keep Erlang maps for lookups, and add a hidden atom key that holds the insertion order. `buoy_rt:object/1`, `set/3`, `delete/2`, and `JSON.parse` maintain it. Array-index keys come first in ascending order, and the other keys follow in insertion order, as OrdinaryOwnPropertyKeys in ECMAScript requires. An object literal gets its order at compile time. `strict_eq` and Map hashing ignore the hidden key. The same change adds the replacer, the reviver, `toJSON`, and the `[Object: null prototype]` label of `console.log`. Files: `runtime/src/buoy_rt.erl`, `buoy_object.erl`, `buoy_json.erl`, `buoy_console.erl`, `lower/expr.rs`; contract sections 3, 13, and 14.

**3.2 Module setup and function properties.** Top-level code may change a module-level value before any function reads it, and the module then stores the final value in `persistent_term` again. A change from a function stays BUOY202. `Object.assign(f, props)` and `f.x = v` build the function with properties of contract section 3, so `assert(x)` and `assert.sameValue(a, b)` both work. Files: `lower/mod.rs`, `buoy_rt.erl`, `buoy_object.erl`.

**3.3 Classes.** One declaration has two uses: `new C()` makes a value, and `spawn(C)` makes an actor. An instance is a map of its fields plus the hidden atom key `'$class'`, as an error holds `'$error'`. A call `r.m(args)` on a place uses the write-back form of contract section 6 when `m` rebinds `this` in any class of the program. A pre-pass of the module graph builds one class table, and each class gets a flat method table. `super.m(args)` is a direct call of the base method, and `super(args)` runs the base initializers and constructor on the same `This`. A base method dispatches `this.m()` on `'$class'` only when a subclass overrides `m`. A base may be a program class, a global error class, `EventEmitter` (3.10), or an Effect class factory (Phase 4). Any other base stays BUOY280. A static method is a module function. A static field that nothing writes is a module-level const, and a written static field stays BUOY202 with the singleton fix. `buoy_rt:get/2` and `set/3` consult the accessor table of the class, and a setter returns the new `This`. Object-literal accessors and object-literal methods that use `this` follow the same rules. `Object.freeze` sets a hidden flag, and a later write throws `TypeError`, as in strict mode. Spread and `structuredClone` drop `'$class'`. `m.get(k)` stays a place only when `m` is not an instance of a program class. Files: `lower/class.rs`, `graph.rs`, `lower/place.rs`, `buoy_rt.erl`, `buoy_object.erl`, `buoy_console.erl`.

**3.4 Regular expressions.** OTP `re` uses PCRE2 since OTP 28, and on OTP 29 it matched lookbehind, named groups, and `\p{L}`. The compiler translates a literal at compile time, because oxc parses regular expressions. `new RegExp` translates at run time, and `persistent_term` caches the compiled patterns. The translation keeps the JavaScript meaning: `\d`, `\w`, and `\s` use the JavaScript sets, `.` excludes line terminators, `$` uses `dollar_endonly`, `[^]` becomes `[\s\S]`, and `u` selects UTF-8 mode. The set operations of the `v` flag are a compile error. The runtime expands `$1`, `$&`, and `$<name>`. `exec` and `test` on a `g` or `y` regex change `lastIndex`, so they are mutators on a place, and BUOY234 rejects them on a module-level regex. Indexes follow the string model of 3.14. Files: `runtime/src/buoy_regexp.erl` (new), `buoy_string.erl`, `lower/expr.rs`, `library.rs`.

**3.5 Closure cells.** An inline closure that changes variables of its enclosing function gets a scoped cell. Before the call, the enclosing function stores those variables in the process dictionary under a fresh ref. The closure reads and writes them there, and the function reads them back after the call returns or throws. Contract section 7 uses the same mechanism for `try`. The result is exact for each callback that runs before the call returns, because every Buoy call blocks. A closure that runs later, or in another process, finds no cell and throws `ERR_BUOY_UNSUPPORTED` with the name of the variable. BUOY255 and BUOY256 still reject the cases that the compiler sees. `forEach` with an inline callback lowers to a loop. Files: `lower/capture.rs`, `lower/function.rs`, `buoy_rt.erl`.

**3.6 Promises and timers.** `await p.then(f)` is `f(await p)`, `.catch(g)` is a `try`/`catch`, and `.finally(h)` is a `try`/`finally`. `new Promise(executor)` makes `{'$promise', Ref}` and runs the executor at once. `resolve` and `reject` send `{'$settle', Ref, Outcome}` to the process that made the promise, from any process. `await p` receives on `Ref`, and a second `await` reads the stored outcome. An actor method that returns a pending promise answers its caller when the promise settles, which is the deferred reply of OTP. An `await` on a promise that another process made throws `ERR_BUOY_UNSUPPORTED`, unless the promise came as an actor reply. Timers use `erlang:send_after/3` to the owner process. The owner runs due callbacks when it next waits: an actor between turns, and top-level code inside any blocking runtime call. The program drains the pending timers before it halts, except the timers after `unref()`. `queueMicrotask`, `setImmediate`, and `process.nextTick` use a queue that drains at the end of the current job. In an actor, a callback `() => this.m(args)` compiles to a cast to the actor itself. Files: `runtime/src/buoy_promise.erl` and `buoy_timer.erl` (new), `buoy_task.erl`, `buoy_actor.erl`, `buoy_main.erl`, `lower/expr.rs`.

**3.7 Date and Intl.** Each `Date` getter and setter works in UTC and in local time through `calendar:universal_time_to_local_time/1`, which follows `TZ` as Node does. The setters are mutators on a place. `Date.parse` adds the fallback formats of V8: the `toUTCString` form, RFC 2822, `YYYY/MM/DD`, and `Month D, YYYY`. `localeCompare` and `Intl.Collator` use the CLDR root collation, from a table that a script derives from the CLDR root data and checks in. `Intl.NumberFormat` and `Intl.DateTimeFormat` get en-US subsets. An `undefined` locale means en-US, a literal locale outside the subset is BUOY322, and a computed locale outside it throws `RangeError`. Named time zones other than UTC come last, because they need the zoneinfo files. Files: `buoy_date.erl`, `runtime/src/buoy_intl.erl` and the generated collation table (new), `buoy_string.erl`, `scripts/generate-collation/` (new).

**3.8 Web APIs.** `URL` and `URLSearchParams` follow the WHATWG parser, written in Erlang and checked against `urltestdata.json` of web-platform-tests. `url.searchParams` is a live sub-place, so a write through it updates `search` and `href`. `fetch` uses `httpc` and blocks until the headers arrive. `text()`, `json()`, `arrayBuffer()`, and `bytes()` are mutators that set `bodyUsed`, and `res.body` waits for the streams of 3.12. `Headers` keeps insertion order and matches names without case. `httpc` speaks HTTP/1.1 only, which the contract records. An `AbortSignal` is `{'$abort', Ref}` with its state in an ETS row, because the controller and every consumer see one state. `abort()` sends a message to each waiting process. `fetch`, `sleep`, `withTimeout`, child processes, and `Effect.tryPromise` accept a signal. Bytes are `{'$bytes', binary()}` for `Uint8Array` and `Buffer`, with `TextEncoder`, `TextDecoder`, `atob`, `btoa`, base64, and hex. `structuredClone` throws `DataCloneError` for functions and symbols. `ai` exports `APICallError` with `isInstance`. Files: `runtime/src/buoy_url.erl`, `buoy_fetch.erl`, `buoy_abort.erl`, `buoy_bytes.erl` (new), `buoy_ai.erl`, `library.rs`.

**3.9 Process.** `process.env` gets computed reads (`os:getenv/1`), the whole object (`os:getenv/0`), writes, and `delete` (`os:putenv/2`, `os:unsetenv/1`). `process.exit(n)` flushes stdout and stderr and halts the VM with status `n`. `process.exitCode` sets the status of a normal end. `cwd`, `chdir`, `platform`, `arch`, `pid`, `hrtime`, `memoryUsage`, `stdout.write`, `stderr.write`, `isTTY`, `columns`, and `rows` map to OTP calls. `process.versions` lists `buoy`, `erts`, and `otp`, and it has no `node` key. `process.on("exit")` listeners run in `buoy_main` before it halts. SIGTERM, SIGHUP, SIGUSR1, SIGUSR2, SIGQUIT, and SIGWINCH arrive through `os:set_signal/2`. SIGINT needs the CLI to stay the parent of the VM and forward Ctrl-C, which changes contract section 1. A read of `globalThis.X` compiles as the global `X`, or as `undefined` for a name that Buoy does not provide. Files: `runtime/src/buoy_process.erl` (new), `buoy_main.erl`, `buoy_rt.erl`, `crates/buoy-cli/src/main.rs`, `lower/expr.rs`.

**3.10 Node modules.** Each module maps to OTP. `node:path` implements `path.posix`, and `path.win32` is a compile error. In `node:fs` and `fs/promises`, the sync form and the promise form are one blocking call over `file` and `prim_file`. An error carries the `code`, `errno`, `syscall`, and `path` of Node. The callback forms and `fs.watch` stay rejected. `node:url`, `import.meta.url`, `import.meta.dirname`, `import.meta.filename`, and JSON imports with `with { type: "json" }` come in this item. `node:crypto` gives hashes, HMAC, `randomUUID`, `randomBytes`, `timingSafeEqual`, and AES-GCM, and `update` is a mutator on a place. `node:child_process` gives the blocking forms, and the output of `spawn` waits for 3.12. `node:events` gives `EventEmitter` as a runtime class: `on`, `off`, and `once` are mutators on a place, and `emit` calls the listeners in order in the process of the caller. `node:async_hooks` gives `AsyncLocalStorage` over the process dictionary, and workers and actor calls copy the stores. `node:os` gives `homedir`, `tmpdir`, `EOL`, `hostname`, and `cpus`. `node:util` gives `isDeepStrictEqual`, `parseArgs`, `format`, `inspect`, and `promisify` of the functions that Buoy implements. `node:zlib`, `node:assert`, and `node:readline/promises` follow. Files: one `runtime/src/buoy_node_<module>.erl` for each module (new), `library.rs`, and `graph.rs` for JSON imports and `import.meta`.

**3.11 Module forms.** `export default <expression>` becomes a module-level const named `default`, and an anonymous function or class gets the name `default`. A re-export from a library forwards the library binding. `import()` with a literal specifier adds the target to the module graph and returns a module namespace value. The top-level code of the target runs on the first import. A computed specifier stays BUOY220, whose fix is a table of literal imports. Files: `graph.rs`, `lower/stmt.rs`, `buoy_main.erl`.

**3.12 Iteration.** A symbol is `{'$symbol', make_ref(), Description}`, and `Symbol.for` uses a registry. Symbol keys live in the map, and `Object.keys` and JSON skip them. A function with a plain `yield` is a JavaScript generator, and a function with only `yield*` stays an Effect body. A generator body runs in a linked coroutine process. `next(v)` is a message round trip, and `{'$generator', Pid}` keeps the identity of the generator object. `for...of` calls `return()` on an early exit, and the process monitors its owner. An object with `next()` or `[Symbol.iterator]()` works through `next` as a mutator on a place. A `for...of` over an iterator in a place uses the iterator up. `for await` accepts arrays, generators, and `{'$stream', Pid, Ref}`, which fetch bodies, child-process output, and Web streams use. `using` and `await using` lower to `try`/`finally`. Files: `runtime/src/buoy_symbol.erl`, `buoy_generator.erl`, `buoy_stream.erl` (new), `buoy_iterator.erl`, `lower/function.rs`, `lower/stmt.rs`.

**3.13 Small syntax.** An enum is a module-level constant object with reverse keys for numeric members, and the compiler inlines a `const enum` member through the module graph. A namespace that holds values flattens into qualified module functions and consts, and a `let` inside it is BUOY202. Labels extend the completions of contract section 12 to `{break, Label, State}` and `{continue, Label, State}`. A `case` that falls through lowers as its own statements followed by the statements of the next case. A BigInt is `{'$bigint', Integer}`: `typeof` gives `"bigint"`, `/` truncates, mixing with numbers throws `TypeError`, and `JSON.stringify` throws. `String.raw` folds at compile time, and a user tag gets a strings array with a `raw` property. Library tags such as `sql` stay BUOY213. `Reflect.get`, `has`, `ownKeys`, `apply`, `set`, and `deleteProperty` compile to existing operations. A computed-name call on a place goes through `buoy_rt:mutate/3`, so a mutator that the code names at run time writes back. `scripts/freeze-expectations.sh` runs Node with `--experimental-transform-types`, because Node's type stripping rejects enums and namespaces. Files: `lower/stmt.rs`, `lower/expr.rs`, `lower/mod.rs`, `buoy_rt.erl`, `scripts/freeze-expectations.sh`.

**3.14 Numbers and strings.** `add`, `sub`, and `mul` return a double when an integer result leaves ±2^53. The exact result rounds once, which gives the IEEE result that JavaScript computes. Integer literals past 2^53 compile to doubles. An integer product or negation that JavaScript gives as `-0` returns `-0.0`. Strings become WTF-8 binaries, and `length`, indexes, `slice`, `charCodeAt`, and regex indexes count UTF-16 code units. Output replaces a lone surrogate with U+FFFD, as Node does. Files: `buoy_rt.erl`, `buoy_string.erl`, `buoy_number.erl`, `buoy_console.erl`, `lower/expr.rs`.

**3.15 `serve`.** `serve({ port, fetch })` from `buoy` starts a listener, and each request runs `fetch(request)` in its own process with the `Request` and `Response` values of 3.8. It is the replacement that BUOY211 names for `node:http` and `node:net` servers and for frameworks such as Express. Files: `runtime/src/buoy_serve.erl` (new), `buoy.erl`, `library.rs`.

**3.16 Home slots.** The design of the TypeScript study: a variable declared from a place keeps that place as its home. The compiler writes the variable back after each change, and it reads the variable again after each change of the home. Start this item only under D4.

## 9. Phase 4: Effect

The runtime model, condensed from the Effect study:

1. Fiber state lives in the process dictionary, next to the actor context. It holds the services by key, the layer memo maps, the scope, the log annotations and spans, the minimum log level, the interrupt flag, and the children that wait to start. A fork copies it. An Effect stays `{'$effect', Thunk}`.
2. A fiber is a linked process that records its Exit and ends normally. A forked child starts when its parent first blocks, as in Effect 4. The program ends when top-level code has returned and every root fiber has ended, which changes contract section 1.
3. Interruption is cooperative. Each fiber has an `atomics` flag that the runtime reads at each step and in each wait. Finalizers run without interruption, and `Fiber.interrupt` waits for them. A kill remains only for an actor stop, an actor crash, and a VM halt.
4. Scope, Ref, Deferred, Queue, PubSub, Semaphore, Latch, and the layer memo map are small processes linked to the runtime root.
5. Option, Result, Exit, Cause, Duration, DateTime, Redacted, HashMap, and the matchers share one term, `{'$data', Id, Fields}`, which prints, pipes, and converts to a string as Effect does.
6. The pure modules, about 650 functions, are a Buoy TypeScript prelude that `crates/buoy-cli/build.rs` compiles to Erlang.

## 10. Phase 5: migration validation

Purpose: prove that an agent can move a real codebase to Buoy with the output of `buoy check`, `buoy explain`, and `buoy fix` as its only guide. The fixture is `tests/migration/before/`: 22 modules and 2,212 lines of a research assistant with AI SDK tool calls and an Effect report service. Its README lists what it exercises.

Two kinds of run:

- Run 5a comes after Phase 2. It measures the diagnostics before Phase 3 changes them. Modules that need a missing API stay blocked, and the output need not match.
- Run 5b comes after the items of section 5. The port must print `expected.stdout`. Repeat 5b after each Phase 3 item that removes codes from the report of the fixture.

The procedure:

1. `scripts/migration-run.sh <run-id>` (new) creates `/tmp/buoy-migration-<run-id>/`. It copies `tests/migration/before/` there as `after/`, puts a `buoy` wrapper on `PATH`, starts the fake OpenAI server, and sets `OPENAI_BASE_URL` and `OPENAI_API_KEY`. The wrapper appends each command, its exit status, and the JSON `summary` line to `log.jsonl`.
2. A fresh agent session starts in that directory. It sees the code and the commands `check`, `explain`, `fix`, and `run`. It does not see the Buoy repository, so the diagnostics are its only guide.
3. `tests/migration/PROMPT.md` (new) holds the instruction text of diagnostics.md section 9 and three more rules. Keep the output of the program. When a diagnostic does not tell you what to write, run `buoy-note <code> <path:line> "<what was unclear>"`, which appends to `notes.jsonl`. Stop when `buoy run src/main.ts` prints `expected.stdout`, or, in run 5a, when only blocked modules remain.
4. The script copies `log.jsonl`, `notes.jsonl`, and the final `after/` into `tests/migration/runs/<run-id>/`. After a 5b run that matches, it also copies `after/` to `tests/migration/after/`.

The numbers of each run come from its logs:

- Iterations: the runs of `buoy check` over the whole tree.
- Diagnostics at each iteration, from the `summary` lines.
- Fixes that `buoy fix` wrote.
- Unclear diagnostics: the notes of the agent, plus each diagnostic that keeps its code and its line across two checks after its file changed.
- Check gaps: a state where `buoy check` exits 0 and `buoy run` does not print `expected.stdout`. Each gap is a silent divergence. It gets a register program and a Phase 2 fix before the next run.

The fix loop: each unclear diagnostic changes its message, help, fix, or explain page, and the page gets an example of the case. Then a fresh agent runs again.

Tests:

- `crates/buoy-cli/tests/migration.rs` (new), on the model of `ai.rs`, starts the fake server and runs `buoy run tests/migration/after/src/main.ts`. It compares stdout and the exit status with `tests/migration/before/expected.stdout`, and it expects `buoy check tests/migration/after/src` to exit 0.
- The snapshot of WP 1.4 follows the report for `before` as Buoy grows.

Exit criteria:

1. Run 5a: each unclear diagnostic of the run is fixed, and each module that is not blocked compiles.
2. Run 5b: `migration.rs` passes, and the last run has no unclear diagnostic and no check gap.
3. `tests/migration/runs/` keeps every run, so the trend of the iterations shows.
