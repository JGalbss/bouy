# Bouy on BEAM: the compiler and runtime contract

Status: the working contract for the BEAM runtime, 2026-10-16. It replaces the "now" decision of ADR 0001. Bouy no longer runs on Node, Bun, or V8, and the product has no Node or V8 dependency. Node appears only as a test oracle and as a benchmark baseline.

This file is the contract between the compiler (`crates/bouy-compiler`), the CLI (`crates/bouy-cli`), and the runtime (`runtime/`). Every name in this file is normative. A change to a name changes this file in the same commit.

## 1. Pipeline

`bouy run app.ts [args...]`:

1. The CLI resolves the module graph from the entry module. It follows relative imports (`./x.ts`, `./x.js`, `./x`, `./dir/index.ts`), relative re-exports (`export { a, b as c } from`, `export * from`, and `export * as ns from`), and library imports (section 11). Any other import is error `BOUY201`. A module exports its named declarations, and `export default` of a named function or class declaration exports it as `default`, which a default import reads. A re-export that names only types, such as `export { type Point } from "./types.ts"`, is erased.
2. The compiler parses each module with oxc, runs oxc semantic analysis, checks the Bouy subset (section 10), and lowers the module to one Erlang source file.
3. The CLI writes the Erlang files to `<project>/.bouy/build/src/`. The project root is the nearest ancestor directory of the entry that holds a `package.json`, or else the entry's directory.
4. The CLI starts one VM: `erl +Bd -noshell -noinput -mode minimal -boot no_dot_erlang -pa <runtime ebin> -eval "bouy_main:start()" -extra <build dir> <entry module> <entry path> <module,module,...> [args...]`, with `ERL_CRASH_DUMP_SECONDS=0`, so a VM that fails to boot leaves no `erl_crash.dump`. `-mode minimal` starts the kernel without distribution and without `inet_db`, which `bouy_ai_openai` adds to the kernel supervisor on its first request (section 14), and `no_dot_erlang` reads no `.erlang` file. The `erl` script searches for its root directory with shell commands on each start, so the CLI starts the VM with the root directory that the runtime cache recorded: when the real path of `erl` is `<root>/bin/erl`, it runs `<root>/erts-<version>/bin/erlexec` with the variables that the script sets, `ROOTDIR`, `BINDIR`, `EMU=beam`, and `PROGNAME=erl`, and else it runs `erl` with `ERL_ROOTDIR=<root>`, unless the environment sets `ERL_ROOTDIR`. On Unix, the CLI replaces its own process with the VM, so a signal to the CLI reaches the VM. `bouy_main:start/0` gives SIGTERM its default action, so SIGTERM ends the VM at once, and it sends the OTP reports to stderr, never into the output of the program. It reads these arguments with `init:get_plain_arguments/0`. It compiles each listed module whose source changed in the VM with `compile:file/2`, writes the `.beam` file and an MD5 stamp of the source to `.bouy/build/ebin/` through a temporary file and a rename, loads the module, starts the runtime with `bouy_app:start/2` (section 8), runs the entry module, and halts. One VM start serves both compilation and execution. Generated code that does not compile is a compiler bug: `bouy_main` prints the errors of `compile:file/2` and halts with status 2. Any other failure before the program runs, such as a build directory that is not writable, prints `bouy: cannot start the program: <reason>` and halts with status 1, so the VM leaves no `erl_crash.dump`.
5. The program ends when the top-level code of the entry module returns. Then the runtime stops every actor and halts with status 0. An uncaught error in top-level code prints `Uncaught <name>: <message>` to stderr and halts with status 1. A compile diagnostic prints `<path>:<line>:<column>: <code>: <message>` to stderr, and the CLI exits with status 2 before it starts the VM. An entry path that is not a file prints `bouy: cannot find the file <path>` and exits with status 2. The exit status is the status of the VM. A signal that ends the VM, such as SIGTERM, or the SIGINT of Ctrl-C (`+Bd` turns off the BREAK menu), ends the program as it ends Node, and a shell reports 128 plus the signal number.

The CLI embeds the runtime sources, `runtime/src/*.erl`, `*.hrl`, and `bouy.app.src`, through `crates/bouy-cli/build.rs`. On the first run, the CLI writes them to `$XDG_CACHE_HOME/bouy/runtime-<hash>/src/` (default `~/.cache/bouy/runtime-<hash>/`) and compiles them into `runtime-<hash>/ebin/` with `erlc`, with `bouy.app.src` copied to `ebin/bouy.app`, and writes `code:root_dir()` and the erts version of `erl` to `runtime-<hash>/release`, one on each line. A runtime without the `release` file starts `erl` as it is. It builds in a private directory and renames it into place, so concurrent first runs are safe, and a failed build removes the private directory. The hash is FNV-1a over the embedded file names and contents and the real path of the `erl` that runs the program, which names the OTP release in Homebrew, asdf, and kerl installations. The installed OTP compiles the runtime, so the `.beam` files always match the installed OTP release. An empty or relative `XDG_CACHE_HOME` is ignored, as the XDG Base Directory specification says. The build of the CLI fails when `runtime/src` holds no runtime sources. `BOUY_RUNTIME=<dir>` names a directory of compiled runtime `.beam` files that replaces the cache, for development. An empty `BOUY_RUNTIME` is unset, and a directory without `bouy_main.beam` is an error before the VM starts. The CLI finds `erl` on `PATH`, or uses `BOUY_ERL`, and finds `erlc` next to `BOUY_ERL` or on `PATH`.

`process.argv` is the list of binaries `[<<"bouy">>, EntryPath | Args]`, so `process.argv.slice(2)` is the program arguments, as in Node. `bouy run <entry> [args...]` passes each argument after the entry as it is, `--help`, `-h`, and `--` included. The CLI replaces each invalid UTF-8 sequence of an argument with one U+FFFD, as Node does. `bouy_main:start/0` stores `process.argv` in `persistent_term` under `{bouy, argv}`, and `bouy_rt:argv()` reads it. `bouy_main:start/0` also sets `standard_io` and `standard_error` to `{encoding, unicode}`, so output is UTF-8 under any locale, as with Node. `console.log` in an actor writes to the device of the top-level code, not through the group leader of the application. A write to a closed stdout, as in `bouy run app.ts | head -1`, is dropped, and the program goes on, as in Node.

`BOUY_MAX_MEMORY` caps the memory of the VM, in bytes with an optional `K`, `M`, `G`, or `T` suffix (default `4G`). `bouy_guard` gives every process a `max_heap_size` of the limit and stops the VM when `erlang:memory(total)` passes it: the VM prints `bouy: the program used more than <n> MiB of memory and was stopped; set BOUY_MAX_MEMORY to change the limit` and halts with status 1. Test runners that start many VMs at once set a smaller limit.

`bouy check app.ts` runs steps 1 and 2 and prints diagnostics. `bouy build app.ts` runs steps 1 to 3 and prints the paths of the Erlang files. Both exit with status 2 when there is a diagnostic.

`run`, `check`, and `build` take `--semantics value|reference` before the entry. `value`, the default, is sections 2 to 16 of this contract. `reference` is the JavaScript engine of [ADR 0003](../adr/0003-run-typescript-on-beam.md), which section 17 describes: objects live in a heap in each process and have identity, and promises run on a job queue in each process. It compiles one module, and it imports only `spawn` and `stop`, and the probes `heapStats` and `vmMemory`, from "bouy".

Every value has value semantics. A mutation changes the variable or the field that holds the value. Another variable that held the same value keeps the old one. This is the largest difference from JavaScript, and it is what isolates actors: a message cannot share mutable state, because no value changes in place.

Known differences from JavaScript. Each one is a documented limitation:

- `===` on arrays and objects compares contents, because values have no identity.
- Object keys iterate in Erlang term order (sorted), not in insertion order. This shows in `Object.keys`, `for...in`, `JSON.stringify`, and `console.log`.
- `string.length` and string indexes count Unicode code points, not UTF-16 code units. The two differ only for characters outside the Basic Multilingual Plane.
- Integers have arbitrary precision. `2 ** 53 + 1` is exact. Text still converts as JavaScript converts it: `Number(s)`, `parseInt`, `parseFloat`, and `JSON.parse` give the nearest double beyond 2^53.
- An integer has no negative zero, so `0 * -1` is `0` where JavaScript has `-0`. Float operations and `Math.round`, `floor`, `ceil`, and `trunc` keep `-0.0`.
- `console.log` prints an error as `Name: message` and its own fields, without stack frames.
- Bouy has no regular expressions. A string method throws a `TypeError` for a pattern that is not a string.
- `localeCompare` compares code points. `toUpperCase` and `toLowerCase` use the Unicode case mapping without the final-sigma rule.
- `Date` supports `Date.now()`, `new Date()`, `new Date(ms)`, `new Date(isoString)`, `getTime`, `valueOf`, `toISOString`, `toJSON`, and `toString`, all in UTC, for the whole time range of ±8.64e15 ms. Other members throw a `TypeError`. `new Date(text)` reads the date time string format of ECMAScript with the leniencies of V8: a day up to 31 rolls into the next month, `24:00` ends the day, and `t`, `z`, and a space separator are accepted. Text in another format, such as `2020/01/02`, gives an invalid date, where V8 tries more formats.
- A `JSON.parse` error has the V8 message for an unexpected token or for the end of input, such as `Unexpected token ']', "[1,]" is not valid JSON`. V8 has more messages, such as `Expected ':' after property name in JSON at position 5`. For some text, such as `nope`, Bouy reports the end of input where V8 reports an unexpected token. So the message can differ from Node. `JSON.parse` supports no reviver function, and `JSON.stringify` supports no replacer function or array: each throws a `TypeError`. A reviver or replacer that is not callable is ignored, as in JavaScript.
- `Math` functions and `parseInt` beyond 2^53 reproduce V8 on arm64, where the compiler fuses `a * b + c` into one rounding. On x86-64, Node can differ from Bouy in the last bit.
- Arrays have no holes. `Array(n)`, `new Array(n)`, a write past the end, `arr.length = n`, and `delete arr[i]` leave `undefined` items, and `map`, `filter`, `some`, `indexOf`, and the other iteration methods visit them. A list cannot mark a missing item.
- An array is a linked list and a string is a UTF-8 binary, so `push`, `xs[i]`, `s[i]`, and `s.length` take time in proportion to the length. A loop that indexes a long array or string is quadratic. Iterate with `for...of`, `map`, or `reduce`, or split a string with `split("")` once.
- `Object.freeze` returns its argument unchanged. A write to a frozen object succeeds, where strict-mode JavaScript throws a `TypeError`. Values are copies, so freezing protects nothing that Bouy shares.
- Objects have no prototype chain. `Object.create` takes only `null` or `Object.prototype` and gives an empty object; another prototype throws a `TypeError`. `Object.setPrototypeOf` returns its first argument unchanged. `console.log` prints the results of `Object.create(null)` and `Object.groupBy` without `[Object: null prototype]`.
- An iterator is a value too. Only `it.next()` on a variable or a field advances it. `for...of`, a spread, and an iterator helper read the items that are left without using them up.
- A function that is not a module-level declaration has the `name` `""` and prints as `[Function (anonymous)]`. The `length` of every function is `undefined`. An Erlang fun keeps no source name, and every compiled function takes one argument list.
- `this.m` read as a value inside a class is a fun over `This` as it is at that moment, so a later change of the fields does not reach it.
- A method call with a computed name that is not a string literal, such as `m[name](k, v)`, does not write the receiver back, so a mutator that it names changes nothing. Inside a class, `this[name](args)` calls the method through `'C#dispatch'/3` and keeps the change of `this`.
- `m.get(k)` is a place for any `m` (section 6): a write through it, such as `m.get(k).push(v)`, calls `m.set(k, value)`, also on a value that is not a Map.
- A nested function declaration exists from just before the first statement of its block that uses it, and it keeps the values that it captures then (section 12). JavaScript creates it when the block starts and reads the variables when it runs.
- The compiler inlines a module-level `const` with a literal initializer. A function that reads such a const before its declaration runs gets the value, where JavaScript throws a `ReferenceError`. A const with another initializer throws the `ReferenceError` as in JavaScript.

## 4. Calling convention

- Every compiled function and every function value takes one argument: the list of arguments. `bouy_rt:arg(N, Args)` returns argument `N` (1-based) or `undefined`.
- A default parameter compiles to `case bouy_rt:arg(N, Args) of undefined -> Default; V -> V end`. A rest parameter compiles to `bouy_rt:rest(N, Args)`, which returns the arguments from position `N` on.
- A call to a function declared in the same module compiles to a local call `'foo'([A, B])`. A call to a function imported from another Bouy module compiles to a remote call `'bouy@other':'foo'([A, B])`. A call to a library function compiles to a remote call to its Erlang module (section 11).
- A call of any other value compiles to `bouy_rt:call(F, [A, B])`. `call/2` accepts a fun and throws `TypeError: <value> is not a function` for anything else.
- A function used as a value compiles to `fun 'foo'/1` or `fun 'bouy@other':'foo'/1`.

## 6. Mutation and methods

- `let` and reassignment compile to new single-assignment variables (`Count@1`, `Count@2`).
- A place is a local variable, `this`, or a chain of property reads and Map entry reads from one of them: `x`, `x.a.b`, `x[i]`, `this.#items`, `this.#state.users`, `groups.get(k)`. A write through `m.get(k)` reads the entry with `get` and writes it back with `erlang:element(2, bouy_rt:mutate(M, <<"set">>, [K, V]))`, so `groups.get(k)!.push(x)` and `counts.get(k)!.n++` change `groups` and `counts`. An actor ref is not a place, so `ref.add(x)` is an actor call (`bouy_rt:call_method/3`) and not a `Set` mutation. The compiler knows that a value is a ref in two cases. The first is a `const` whose initializer is `spawn(...)` or `supervise(...)` from `bouy`. The second is a variable, a parameter, or a class field whose declared type is `Ref<C>` from `bouy`, alone or in a union with `undefined` and `null`, such as `store: Ref<Store>` or `#peer?: Ref<Peer>`. The type of a field applies to `this.<field>` inside the class that declares it. A library namespace is not a place either.
- `x++` and `++x` compile to `X1 = bouy_rt:sub(X, -1)`, which converts `X` with ToNumber as JavaScript does. When the old value of `x++` is used, it is `T = bouy_rt:to_number(X)` and `X1 = bouy_rt:add(T, 1)`.
- `place = v`, `place += v`, `place++`, and `delete place.k` read the chain, compute the new value, and write it back from the innermost key outward with `bouy_rt:set(Object, Key, Value)` and `bouy_rt:delete(Object, Key)`. Then the compiler rebinds the root variable. Each key expression runs once.
- `r.m(args)`, where `m` is a mutator name and `r` is a place, compiles to `{Result, R1} = bouy_rt:mutate(R, <<"m">>, Args)`. The compiler writes `R1` back to the place, and the expression yields `Result`. The mutator names are `push`, `pop`, `shift`, `unshift`, `splice`, `sort`, `reverse`, `fill`, `copyWithin`, `set`, `add`, `delete`, `clear`, and `next`, which advances an iterator. A string literal key names a method as a static key does, so `xs["push"](1)` is a mutator call.
- The receiver of a mutator may also be a call of a mutator that returns its receiver (`set`, `add`, `sort`, `reverse`, `fill`, `copyWithin`) on a place, or an assignment to a place. The call or the assignment runs first, and then the mutator changes the same place, so `m.set(a, 1).set(b, 2)`, `xs.sort().reverse()`, and `(groups[k] ??= []).push(x)` change `m`, `xs`, and `groups`. Each key expression still runs once.
- `r?.m(args)`, where `m` is a mutator name and `r` is a place, yields `undefined` when the value at the place is `null` or `undefined`. Otherwise it runs the mutator, writes back, and yields the result. The variables that it rebinds come out of a `case` as `{Result, {Vars}}`.
- `Object.assign(place, ...sources)` with the global `Object` is a mutation of the place: `bouy_object:assign/1` returns the merged object, which is the result and the new value of the place. So `Object.assign(this, options)` sets fields of an actor.
- When the right side of a write, or an argument of a mutator, assigns the root variable itself, as in `o.k = (o = other, 5)`, the write changes the old value, which no variable holds any more. The root keeps the value that the right side assigned, as in JavaScript.
- A mutator call or `Object.assign` whose receiver is a value that no variable holds, such as `arr.at(0)!.push(x)` or `(flag ? a : b).push(x)`, is error `BOUY206` when its result is not used, because the change would be lost. The result of a call on a fresh value, such as `const sorted = Object.keys(o).sort()`, is fine.
- Any other method call `r.m(args)` compiles to `bouy_rt:call_method(R, <<"m">>, Args)`, which returns the result only. A computed key that is not a string names a property like any other key, so `handlers[0](x)` calls the item at index 0.
- `this.m` that is not called is a value: `fun(Args) -> erlang:element(1, 'C#m'(This, Args)) end` over the current `This`, so `xs.map(this.label)` and `this.handle.bind(this)` work. A method that rebinds `this` has no such value (`BOUY205`). `this.m?.()` calls the method, because a method always exists. `this[name](args)` with a name that is not a literal compiles to `{Result, This1} = 'C#dispatch'(bouy_rt:to_string(Name), This, Args)` and rebinds `This`. `this.m(a).n(b)`, where every exit of `m` is `return this`, calls `n` on `this` after `m`.
- `this.m(args)` inside a class method compiles to a direct call `'C#m'(This, Args)`. The call returns `{Result, This1}`, and the compiler rebinds `This`. A method that never rebinds `this`, directly or through such a call, leaves `This` as it was, so a call to it compiles to `erlang:element(1, 'C#m'(This, Args))` and does not rebind `This`. A closure may call such a method (section 10, `BOUY205`).
- `call_method/3` and `mutate/3` dispatch on the receiver. A list goes to `bouy_array`, a binary to `bouy_string`, a number to `bouy_number`, `{'$map', _}` to `bouy_map`, `{'$set', _}` to `bouy_set`, `{'$date', _}` to `bouy_date`, `{'$iterator', _, _}` to `bouy_iterator`, and an error map to `bouy_error`, each through the `call/3` or `mutate/3` of that type module (section 11). A ref goes to `bouy_actor:call(Ref, <<"m">>, Args)`, and a `{'$cast', Id}` to `bouy_actor:cast/3`. `{'$namespace', M}` calls the function that `M:'$member'(<<"m">>)` returns. An Effect goes to `bouy_effect:call(<<"m">>, Effect, Args)` (for `pipe`). Another map calls the function in its property `m`. A function and a method value support `call`, `apply`, and `bind`; a method value runs with the first argument of `call` as its receiver, so `Object.prototype.hasOwnProperty.call(o, k)` works. A class supports `captureStackTrace`, which does nothing, because an error records its stack when it is built. Every value has the methods of `Object.prototype`: `hasOwnProperty`, `isPrototypeOf`, `propertyIsEnumerable`, `toLocaleString`, `toString`, and `valueOf`.

## 7. Statements and control flow

Section 12 describes the lowering.

- `if`, `else`, `switch`, conditional expressions, and the logical operators branch with `case`.
- `for`, `while`, `do...while`, `for...of`, and `for...in` compile to named recursive funs. A loop in an actor stays preemptible, because the BEAM scheduler preempts every process after a budget of reductions.
- `throw e` compiles to `erlang:error({'$throw', E})`.
- `try`/`catch`/`finally` compiles to `try ... catch error:Reason:Stack -> E = bouy_rt:caught(Reason, Stack), ... after ... end`. `caught/2` turns `{'$throw', V}` into `V`. It turns an Erlang runtime error (`badarith`, `badarg`, `function_clause`, `{badmatch, _}`, `{case_clause, _}`, `undef`) into an error value named `TypeError`, with two exceptions that JavaScript names otherwise. A `badarg` of `persistent_term:get({Module, <<"x">>})` is a module-level const read before its declaration runs, which is a `ReferenceError`: `Cannot access 'x' before initialization`. An `undef` of a global namespace module is a member that does not exist: `TypeError: Object.fromPairs is not a function`. The `throw` class is reserved for Effect failures (section 13), so a `catch` does not catch them.
- An Erlang exception drops the bindings of the code that raised it, but JavaScript's `catch` and `finally` see the variables as the `try` body left them. So a `try` that rebinds outer variables, and has a `catch` or a `finally` that reads them, records them: `Key = erlang:make_ref()` and `erlang:put(Key, {Vars})` before the `try`, `erlang:put(Key, {Vars})` right after each binding of the body or handler that changes one, such as an assignment, the update of a loop header, or a rebinding earlier in a statement that then throws, `{Vars} = erlang:get(Key)` at the start of the handler and of the `after` block, and `erlang:erase(Key)` in `after`. The key is a fresh ref for each run of the `try`, so recursion and actors cannot mix records.
- A `finally` block that rebinds outer variables cannot be an `after` block, because `after` exports no bindings. Its statements run after the `try`: `Outcome = try {done, try Body catch error:R:S -> Handler end} catch C:R:S -> {raised, C, R, S} end`, then `{Vars} = erlang:get(Key)`, the `finally` statements, and `erlang:raise(C, R, S)` for `{raised, ...}`. A `return`, `break`, or `continue` of the body or handler is rebuilt from the versions that the `finally` statements leave. A `finally` block that itself returns or jumps is error `BOUY206`.
- `async` functions compile like other functions. A BEAM process can block, so a call returns when its result is ready.
- `Promise.all([e1, e2, ...])` compiles each element to a thunk and runs the thunks in parallel processes: `bouy_task:all([fun() -> E1 end, ...])`. `Promise.all(xs.map(f))` compiles to `bouy_task:map(Xs, F)`. `Promise.allSettled`, `Promise.race`, and `Promise.any` compile the same way to `bouy_task:all_settled/1`, `bouy_task:race/1`, and `bouy_task:any/1`, and over `xs.map(f)` to `bouy_task:map_settled(Xs, F)`, `bouy_task:map_race(Xs, F)`, and `bouy_task:map_any(Xs, F)`. Over an array, each worker calls `f` through `bouy_rt:call/2` with the item, the index, and the array, as `map` does, so `Promise.all(xs.map(String))` works. When `f` is an arrow or function literal with at most two parameters and no rest parameter, it cannot read the array, so the compiler passes its parameter count as a third argument, as in `bouy_task:map(Xs, F, 2)`, and each worker gets only its item and its index: no worker copies the array. A receiver that is not an array runs its own `map`, whose results are already settled. The results keep the input order. `Promise.any` returns the first value, or throws an `AggregateError` with the errors in input order in `errors`. An empty `Promise.race` never settles: in an actor, the call waits forever, and outside every actor the program prints `Warning: Detected unsettled top-level await` to stderr and halts with status 13, as Node does. When a thunk throws, the call throws the first error in input order, after every other thunk ends. `Promise.resolve(v)` and `Promise.reject(e)` follow the namespace rule (section 11) to `bouy_task:resolve/1`, which returns `v`, and `bouy_task:reject/1`, which throws `e`.

## 8. The `bouy` module

`import { ... } from "bouy"` imports from the Erlang module `bouy`. Each function takes the argument list.

| TypeScript                                                    | Behavior                                                                                                                                                        |
| ------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `spawn(Class, { args?, name?, mailbox?, restart? })`          | Starts an actor under `bouy_keeper` and returns its ref. `Class` must be an actor class: an error class throws `TypeError: spawn() needs an actor class`.       |
| `ref.method(...args)`                                         | A call: sends a request and waits for the reply.                                                                                                                |
| `cast(ref).method(...args)`                                   | Sends a request without a reply. Returns `true`, or throws `MailboxFull` or `ActorStopped`.                                                                     |
| `stop(ref)`                                                   | Stops the actor at once, also during a turn. Its waiting callers get `ActorStopped`.                                                                            |
| `inspect()`                                                   | An array of `{ id, name, class, status, restarts, mailbox, memory }`.                                                                                           |
| `supervise({ strategy?, maxRestarts?, withinMs?, children })` | Starts a supervisor with one child for each entry of `children`, and returns an object of refs with the same keys.                                              |
| `child(Class, { args?, restart?, mailbox? })`                 | A child specification for `supervise`: `{'$child', Class, Options}`.                                                                                            |
| `schedule(ref, { every } \| { after }, method, ...args)`      | Casts `method` to the actor once after `after` ms, or every `every` ms. Returns the handle `{'$schedule', Pid}`.                                                |
| `cancelSchedule(handle)`                                      | Stops the timer of a `schedule` handle, and returns after the timer has stopped, so no cast of the schedule arrives after a message that the caller sends next. |
| `sleep(ms)`                                                   | Blocks the calling process.                                                                                                                                     |
| `withTimeout(ms, fn)`                                         | Runs `fn` in a new process. When `ms` passes first, it kills that process and throws `CallTimedOut`.                                                            |
| `self(this)`                                                  | Inside an actor method: the ref of the actor. Elsewhere it throws `Error`.                                                                                      |

Details of the functions:

- When a constructor throws, `spawn` and `supervise` throw `ActorFailed` for the method `constructor`. `supervise` then stops the children that it started. The actor stays in `inspect()` as `"stopped"`, so a ref that the constructor gave away keeps the label of the actor.
- An actor that a constructor starts, with `spawn` or `supervise`, belongs to the actor of that constructor: it stops when that actor restarts or stops, so a restart does not leave the actors of the previous start running.
- `mailbox.capacity`, `maxRestarts`, and the times in ms take any number without a fraction, such as `64.0` from JSON. A time may exceed 2^32 ms.
- `supervise` starts the children in key order. The key is the name of the child.
- After `stop`, every call or cast throws `ActorStopped`. Inside an actor, `stop` returns before the process ends.
- `inspect` lists the actors in id order. `name` is the `name` option or `undefined`. `status` is `"running"`, `"restarting"`, or `"stopped"`; a restarted actor is `"restarting"` until its constructor ends. `mailbox` is the length of the message queue, and `memory` is the size of the process in bytes. The table keeps the 1000 stopped actors with the highest ids and forgets older ones, so a program that starts and stops actors forever keeps bounded memory. A call through a ref of a forgotten actor throws `ActorStopped` with the label `actor #<id>`.
- The timer of `schedule` is a process that monitors its owner: the actor whose turn or constructor calls `schedule`, also from a `bouy_task` worker, or else the top-level code. It ends with its owner, and when the actor stops. A full mailbox skips one cast, whatever the overflow of the mailbox, so a timer never waits.

Actor semantics:

- `bouy_main` starts the runtime with `bouy_app:start(normal, [])`, which needs no `.app` file. `application:ensure_all_started(bouy)` also works when `bouy.app` is on the code path.
- An actor is a `gen_server` (`bouy_actor`) whose state holds the class and `This`. Its process runs `'C#new'/1` before it takes a request: in `init/1` for a child of `supervise`, and in `init_alone/2`, before `gen_server:enter_loop/4`, for an actor that `spawn` starts. Then it waits for its first request hibernated, so an actor that takes no request holds only its live data, and it keeps its message queue off its heap (`{message_queue_data, off_heap}`), so a full mailbox does not grow the heap that each garbage collection copies. A call runs `'C#dispatch'/3` and replies with the result.
- A turn is one call or one cast. The process handles one message at a time, so turns never interleave.
- Identity: an id is a positive integer. The ETS table `bouy_actors` maps an id to the mode of the actor, its last pid, the count of its starts, whether it is stopped, and the facts that stay fixed for its life: the class, the module, the constructor arguments, the name, the mailbox policy, the restart type, and the supervisor. The mode is `{running, Pid, Counter, Mailbox}` once the constructor of process `Pid` has finished, `{starting, Pid, Counter, Mailbox}` while it runs, `restarting` while no process serves the actor, or `stopped`. A call or a cast reads only the mode. A restart keeps the id, so a ref stays valid after a restart.
- A thrown error in a turn: the actor replies `ActorFailed` to the caller and exits. `ActorFailed` is an error value with `_tag` `"ActorFailed"`, the actor label in `actor`, the method in `method`, and the original error as `cause`. The supervisor restarts the actor with a new `This` from `'C#new'/1` and the original arguments. Messages in the mailbox of the failed process are lost, and their callers get `ActorStopped`. This is the BEAM model. A call that starts after its caller got `ActorFailed` waits for the restart. A caller that waits for a restart or for a constructor records itself in the ETS table `bouy_watchers` and blocks until the next change of the mode, which each change announces with a message, or until the supervisor of the actor ends. It never polls.
- A method that returns an Effect: the actor runs the Effect in the same turn. A success replies the value. A typed failure replies the failure, the caller throws it, and the actor keeps its state. A defect crashes the actor. A typed failure in a cast has no caller, so the actor drops it.
- Mailbox (`mailbox: { capacity?: number, overflow?: "backpressure" | "reject" }`, default capacity 1024 with `backpressure`): the counter in the mode of the actor, an `atomics` array of one start, counts the requests that the actor has not taken yet. A sender adds one to the count before it sends, atomically with `atomics:add_get/3`, and the actor takes one off when it takes a request, so concurrent senders cannot pass the capacity together. The count belongs to one start of the actor: a new process gets a new counter at zero, because the messages of a dead process are lost. With `reject`, a full mailbox throws `MailboxFull` to a call or a cast. With `backpressure`, a cast to a full mailbox becomes a call, so the sender waits until the actor takes the message. A call always waits. So the mailbox holds at most the capacity plus one message for each blocked sender. A cast to an actor that waits on the sender, as a member of its call chain or through the wait-for graph, goes in at once, because that actor could never take it otherwise. A blocked cast throws `ActorStopped` when the actor stops, and counts as sent when a crash loses it.
- Call cycles: a call carries the chain of actor ids that wait on it. A call to an actor in its own chain throws `CallCycle` instead of a deadlock. A call or a blocked cast from inside an actor also records its wait in the ETS table `bouy_waits`, the wait-for graph, before it looks for a path from the target back to its chain. So of two turns that call each other at once, at least one sees the cycle, and its call throws `CallCycle`. A constructor never throws `CallCycle` for a path in the graph: a call to an actor waits until the constructor of that actor ends, and looks for the cycle while it waits, so the call that waits on a restart throws `CallCycle` and the restart completes. Each wait that a constructor records wakes the callers that wait on that constructor, so they look for the cycle again. The processes of `bouy_task`, `withTimeout`, and the Effect workers (section 13) inherit the chain of their caller. A `Promise.race` that has returned ends the chain of its losers, so a loser that keeps running calls as top-level code does.
- Supervision maps to OTP. `"one-for-one"`, `"one-for-all"`, and `"rest-for-one"` map to the OTP strategies of the same names. `maxRestarts` and `withinMs` (default 3 in 5000) map to `intensity` and `period`. OTP counts `period` in whole seconds, so `withinMs` rounds up. The restart types are `"permanent"`, `"transient"` (the default), and `"temporary"`. A crash exits with the reason `{shutdown, {crashed, Id}}`, and an actor never exits normally, so `"transient"` maps to the OTP type `permanent`. `bouy_root_sup` owns the actor tables and supervises `bouy_keeper` and `bouy_groups`. An actor that `spawn` starts is one process, linked to `bouy_keeper`, which restarts it in a new process after a crash, with a budget for each actor: 3 restarts within 5 seconds, counted as an OTP supervisor counts `intensity` and `period`. So a crashing actor cannot use up the restart budget of another actor, and a slow constructor never blocks the keeper. Each `supervise` call starts an OTP group supervisor under `bouy_groups`. A supervisor that uses up its budget stops its actors: the keeper marks them `"stopped"`, also when a group ends or a temporary child of a group ends, and later calls and casts throw `ActorStopped`. A group supervisor ends with its last actor: when that actor stops, or when a temporary actor crashes. `stop` marks the actor stopped and then kills its last process, or kills the group of the actor, so a constructor that runs never blocks other spawns. A restart that starts after the mark sees it and ends at once.
- A crash prints one line to stderr: `bouy: <class> <name or #id> crashed: <name>: <message>`. The text after `crashed: ` is `String(error)`, so an empty message prints only the name. The runtime drops the OTP supervisor reports of its own supervisors.

The runtime errors are error values (section 3) with the error name in `name` and `_tag`. `<actor>` is the label of the actor, `<class> <name>` or `<class> #<id>`. `<cause>` is `String(cause)`.

| Error          | Own fields                 | `message`                                                                                             |
| -------------- | -------------------------- | ----------------------------------------------------------------------------------------------------- |
| `ActorFailed`  | `actor`, `method`, `cause` | `<actor> failed in <method>: <cause>`                                                                 |
| `ActorStopped` | `actor`                    | `<actor> is stopped`                                                                                  |
| `MailboxFull`  | `actor`                    | `<actor> has a full mailbox`                                                                          |
| `CallCycle`    | `actor`                    | `<actor> is busy with a call that waits on this call. Use cast() or pass the data in the first call.` |
| `CallTimedOut` | `ms`                       | `the call did not finish within <ms> ms`                                                              |

## 9. Classes

A class without `extends` is an actor class. `new` on an actor class is error `BOUY203`. Use `spawn`.

- `'C#new'(Args) -> This` binds the constructor parameters, runs the field initializers in order, runs the constructor body, and returns `This`. `This` is a map from field key to value. A public field `x` has the key `<<"x">>`. A private field `#x` has the atom key `'#x'`, which JSON and object literals cannot make: `this.#x` is `maps:get('#x', This, undefined)`, and a write is `maps:put/3`. The runtime lists only binary keys as properties, so `JSON.stringify(this)`, `Object.keys(this)`, a spread, `in`, and `console.log` do not show a private field. `this.constructor` in an actor class compiles to the class value `{'$class', Module, <<"C">>}`.
- `'C#dispatch'(Method :: binary(), This, Args) -> {Result, This1}` has one clause for each public method. Another name throws `TypeError: <class>.<method> is not a function`.
- `'C#m'(This, Args) -> {Result, This1}` exists for each method, private methods included.

A class with `extends Error`, `extends Data.TaggedError("Tag")`, or `extends Data.Error` is an error class. A base resolves as any name does: `Error` is the global class only when no declaration of the module shadows it, and `Data` must be the import of `Data` from "effect". `new E(args)` compiles to `'E#new'(Args)`, which builds an error value with `bouy_error:new([{'$class', Module, <<"E">>}, {'$class', bouy_error, <<"Base">>}], Message, Fields)`: the classes of the error, with `Base` the global error class that `E` extends (`Error` for `Data.TaggedError` and `Data.Error`), `name` set to the class name, and `_tag` for a tagged error. `instanceof` tests the classes, so renaming an error keeps its class, and two classes with one name in two modules stay apart. `this.constructor` in the constructor is the class, and `Object.setPrototypeOf(this, E.prototype)` changes nothing. Without a constructor, `Message` is the first argument as a string (`<<>>` for `undefined`) for `extends Error`, and the `message` field of the first argument for `Data.TaggedError` and `Data.Error`, whose first argument is also `Fields`. An error class may declare `readonly` fields without initializers, which are types only, and fields with initializers, which `'E#new'/1` sets after the error is built. It may also declare a constructor whose first statement is `super(...)`. `super(args)` builds the error from `args` as above, and the rest of the constructor runs with `this` bound to the error, so `this.name = "E"` and `this.field = value` set fields. With a global base, the second argument of `super(message, options)`, or of `new E(message, options)` without a constructor, gives the field `cause` when `options` has the key `cause`, as the global error classes do. The parameter properties of the constructor, such as `constructor(public status: number)`, set their fields after the field initializers. An error class declares no methods.

The constructor of any class is the one with a body: the overload signatures before it are types.

The global error classes `Error`, `TypeError`, `RangeError`, and `SyntaxError` are bases of an error class too. `extends` of any other class is error `BOUY206`.

The namespace module contract:

- `Ns.f(args)` compiles to the remote call `Module:'f'(Args)` for the functions that `GLOBAL_FUNCTIONS` in `library.rs` lists for the global or the library namespace, such as `log` of `console` and `succeed` of `Effect`. A unit test checks that the runtime module exports each one. A call of another member, such as `console.table` or an internal helper of the module, is `BOUY206`.
- `Ns.x` that is not called compiles to `Module:'$member'(<<"x">>)`, which returns a constant or `fun Module:'x'/1`. A constructor namespace also has `name`, such as `<<"Map">>`, and `prototype`, `{'$prototype', {'$namespace', Module}}`. A call of a member that the module lacks throws `TypeError: <Ns>.<f> is not a function`.
- `new Ns(args)` compiles to `Module:new(Args)`.
- `Ns(args)`, a call of a global constructor as a function such as `String(x)`, `Number(x)`, `Array(n)`, `Object(x)`, or `Date()`, compiles to `Module:'$call'(Args)`. `bouy_rt:call/2` on `{'$namespace', M}` calls `M:'$call'(Args)`, so `xs.map(String)` works. `typeof` says `"function"` for a constructor namespace and for a namespace whose module exports `'$call'/1`, such as `openai`.
- Each type module (`bouy_array`, `bouy_string`, `bouy_number`, `bouy_map`, `bouy_set`, `bouy_date`, `bouy_error`, `bouy_iterator`) also exports `call(Name :: binary(), Receiver, Args) -> Result` for its methods and `get(Receiver, Key) -> Value` for its properties, such as `length` and `size`. A module with mutators exports `mutate(Name, Receiver, Args) -> {Result, Receiver1}`. `mutate/3` on a name that is not a mutator returns `{call(Name, Receiver, Args), Receiver}`.

## 12. Lowering control flow

The compiler keeps a map from each oxc `SymbolId` to the Erlang name of its current version. An assignment creates a new version. A construct that rebinds variables declared outside it returns their new versions, and the code after the construct binds them.

A statement completes normally, or it completes abruptly through `return`, `break`, or `continue`. A `throw` is an Erlang exception, so it needs no completion. Each lowered block knows its frame:

- In the top-level sequence of a function body, `return e` becomes the final expression `E`, and falling off the end yields `undefined`.
- An `if` or `switch` whose branches all complete normally is an expression that yields the tuple of the variables it rebinds: `{X@2, Y@1} = case ... end`.
- An `if` or `switch` with an abrupt branch yields a tagged completion: `{next, {X@2, Y@1}}`, `{return, V}`, `{break, State}`, or `{continue, State}`. The compiler lowers the code after the construct once, inside the `{next, ...}` clause of a `case` on the completion. The other clauses forward the completion to the enclosing frame. In a function frame, `{return, V}` yields `V`. `State` is the tuple of the variables of the target: the state of a loop, or the variables that a `switch` rebinds.
- Two shapes need no completion. An `if` with an abrupt branch and at most one branch that can reach its end lowers the code after it once, inside that branch, and each jump lowers in place: `case C of true -> V; false -> Rest end` for `if (c) return v; rest`. A `switch` with a `default` whose every case ends in a jump other than `break` is a plain `case` whose clauses lower in place.
- A loop is a named fun over a state tuple of the variables that the loop rebinds: `Loop = fun Loop({I, Sum}) -> ... end`. Falling through and `continue` run the update expression and call `Loop` with the new state. `break` yields `{break, State}`. `return e` yields `{return, V}`. After the loop, a `case` binds the state from `{break, State}` and forwards `{return, V}`. A loop without `return` binds the state directly: `{break, {I@9, Sum@4}} = Loop({I@1, Sum@1})`. The fun of `for...of` and `for...in` also takes the remaining items: `Loop([X | Rest], State)` and `Loop([], State) -> {break, State}`, over `bouy_rt:to_list/1` or `bouy_rt:keys/1` of the right side.
- A `try` block that rebinds outer variables yields the tuple of the rebound variables from both the body and the handler. The handler starts from the recorded versions of section 7.
- A conditional expression or a logical operator whose right side rebinds variables yields `{Value, {Vars}}`, and so does a logical assignment such as `cache ??= (hits++, "filled")`. An expression statement `a && f()`, `a || f()`, or `c ? f() : g()` lowers as an `if`.
- A `switch` tests its cases in source order and takes `default` only when no case matches. The tests that share a body with `default` run at their place in that order.
- The function declarations of a block are created just before the first statement of the block that uses them, so that they capture the latest values, and a function can be called before its declaration. A function that a used function calls is created no later. Functions that call each other are created together as one named fun that returns all of them: `Group = fun Group() -> {fun(Args) -> {F, G} = Group(), ... end, ...} end`, then `{F, G} = Group()`. A function that nothing uses is created at its declaration. A function used before a variable that it reads is declared is `BOUY205`.

A pre-pass over the subtree of a construct finds the variables it rebinds. They are the targets of every write reference to a symbol declared outside the subtree, plus the root variable of every place that a mutation or a mutator call writes (section 6). `this` counts as the variable `This`.

An Effect is `{'$effect', Thunk}` (section 3). Running it calls `Thunk()`, which returns `{ok, Value}` or `{error, Failure}`. A defect, from `Effect.die` or from an exception in a function such as the one that `Effect.sync` or `Effect.map` takes, is a JavaScript exception, so it passes every combinator that does not handle it. An error value is an Effect too, which fails with itself, as a `Data.TaggedError` instance does in Effect. `Effect.result` gives the object `{ _tag: "Success", success }` or `{ _tag: "Failure", failure }`. A DurationInput is a number of milliseconds, a string such as `"100 millis"` or `"1.5 seconds"`, or a duration.

A generator function is the body of an Effect. A call of it returns `bouy_effect:generator(fun() -> Body end)`, an Effect whose thunk binds the parameters and runs the statements. The `return` value is the success value. So `Effect.gen(body)` calls `body`, and the function of `Effect.fn` calls `body` with its arguments, each time the Effect runs. In the body, `yield* e` compiles to `bouy_effect:bind(E)`, which runs `e` and returns its value. A failure ends the body with `erlang:throw({'$fail', Failure})`, and a defect with `erlang:throw({'$die', Defect})`. The thunk of `generator/1` turns the first into `{error, Failure}` and raises the second again as a JavaScript exception. A `catch` clause lowers to the `error` class only (section 7). In a generator body, a `finally` block lowers to the outcome form of section 7, with a first clause that rethrows the `throw` class. So no `catch` or `finally` of the body runs after a failed `yield*`, as in Effect, which abandons the generator. A JavaScript `throw` in the body is a defect, and the `catch` and `finally` of the body see it.

The compiler rejects `yield` without `*`, a `yield*` in a function nested in a generator, an `async` generator, and a generator method with `BOUY206`. oxc reports a nested `yield*` as the use of a reserved word, and the compiler reports it as `BOUY206`. A generator function is a closure, so the capture rule of `BOUY205` applies to it, and `this` in it is `BOUY206`.

A worker of `all`, `forEach`, `zip`, `race`, and `timeout` adopts the actor context of its caller and is linked to it, as the workers of `bouy_task` are. An actor method that returns an Effect runs it in the same turn (section 8).

Known differences from Effect. Each one is a documented limitation:

- A killed worker runs no finalizers: an `ensuring` finalizer inside work that a timeout, a race, or a failed sibling interrupts does not run, where Effect runs it.
- `runSync` and `runPromise` block until the Effect ends. `runSync` also runs an asynchronous Effect, where Effect throws, and `runPromise` without `await` ends before the next statement runs.
- `console.log` prints an Effect as `[Effect]`, a schedule as `[Schedule]`, and a Result with its fields, `{ _tag: 'Success', success: 1 }`, where Effect prints `{ _id: 'Result', _tag: 'Success', value: 1 }`. A `Data.TaggedError` instance prints as an error (section 3), where Effect prints only its fields, and `String()` of a SchemaError is `SchemaError: <message>`, where Effect gives `SchemaError(<message>)`.
- `Effect.all` over a record runs the Effects in key order, and `Schema.Struct` checks and returns its fields in key order, because object keys are sorted (section 3). With several invalid fields, the issue in the message can differ from the one Effect reports. Decoding stops at the first issue, and a SchemaError has no `issue` field.
- `Schedule.fixed` waits the whole interval after each failure, as `spaced` does. The function of `Effect.promise` and `Effect.tryPromise` gets no AbortSignal. `Effect.gen({ self }, body)` ignores `self`.

`bouy_ai` implements a subset of `ai` 7.0.142, and `bouy_ai_openai` implements a subset of `@ai-sdk/openai` 4.0.95. The programs in `tests/equivalence/ai` run with Node and the real packages and with `bouy run`, against one fake server, and print the same output (section 15).

The rules:

- Endpoint. `@ai-sdk/openai` 4.x sends `openai(model)` and `openai.languageModel(model)` to the Responses API. Bouy sends every model to the Chat Completions API, `POST <baseURL>/chat/completions`, as `openai.chat(model)` does, because every OpenAI-compatible server serves it. The equivalence programs use `openai.chat`. A model that only the Responses API serves fails with an `APICallError`.
- Configuration. The provider reads `baseURL`, or else `OPENAI_BASE_URL`, when it is made, and drops one trailing slash. The default is `https://api.openai.com/v1`. It reads `apiKey`, or else `OPENAI_API_KEY`, when it sends a request, as the package does, so a missing key throws `AI_LoadAPIKeyError` from `generateText`.
- A model is `#{<<"specificationVersion">> => <<"v4">>, <<"provider">> => <<"openai.chat">>, <<"modelId">> => Id, '$generate' => Fun}`. The `name` option of `createOpenAI` replaces `openai` in the provider. `generateText` calls the fun under the atom key, so a model of another provider, such as a gateway string, throws a `TypeError`.
- Requests. The provider sends the body of the package: `model`, `messages`, `tools`, `tool_choice`, and the settings. A reasoning model (the o series, and GPT 5 and later except the chat variants without a minor version) gets the system prompt as a `developer` message, sends `max_completion_tokens`, and drops the sampling settings with a warning in `warnings`. User messages hold text only: an image or a file part throws a `TypeError`.
- HTTP. The provider calls OTP `httpc`. It starts `inets` on the first request, and `ssl` for an `https` URL, where it verifies the server with `httpc:ssl_verify_host_options(true)`. Before them it adds `inet_db`, the resolver configuration that the minimal kernel leaves out (section 1), to the kernel supervisor. A program without AI calls does not start them. `bouy_json` encodes the body and decodes the response, so the values follow `JSON.stringify` and `JSON.parse`.
- Steps. Each step calls the model, parses each tool call, and runs the `execute` functions of the step in parallel processes (`bouy_task:all/1`), as `Promise.all` runs them. `execute` gets the input and `{ toolCallId, messages }`. The next step starts while every tool call of the step has an output and no stop condition holds. The default stop condition is `stepCountIs(1)`. A call of an unknown tool, input that is not JSON, and an `execute` that throws give a `tool-error` output, and the model gets the error message, as in `ai`. A `toolChoice` of `"required"` or of one tool throws `AI_ToolChoiceViolationError` when the model calls no matching tool.
- Errors. An AI SDK error is an error value (section 3) whose classes are `{'$class', bouy_ai, <<"APICallError">>}` and `Error`, and whose name is `AI_APICallError`, with the fields of the package. A response with a status other than 2xx, a response that is not JSON, and a failed connection throw `AI_APICallError` with `url`, `requestBodyValues`, `statusCode`, `responseHeaders`, `responseBody`, `isRetryable`, and `data`. The message is the `error.message` of an OpenAI error body, or else the status text. `generateText` retries a retryable `APICallError` (status 408, 409, 429, or 500 and above, or a failed connection) `maxRetries` times, default 2, after 2 s and then 4 s, or after the delay of a `retry-after-ms` or `retry-after` header when that delay is below 60 s or below the backoff. Then it throws `AI_RetryError` with `reason`, `errors`, and `lastError`. A bad prompt throws `AI_InvalidPromptError`, and a bad `maxRetries` throws `AI_InvalidArgumentError`.
- The result and each step hold the values of the getters of `ai` as fields: `text`, `content`, `toolCalls`, `toolResults`, `finishReason`, `usage`, `response`, `steps`, and the others.

Known differences from the packages. Each one is a documented limitation:

- `openai(model)` and `openai.languageModel(model)` use Chat Completions, as described above.
- `result.output` is `undefined` where `ai` throws `NoOutputGeneratedError`, and `Object.keys` of a result or a step lists the fields that `ai` computes in getters. A step has no `performance` field.
- The error classes, such as `APICallError`, are not exports. Test `error.name`, such as `"AI_APICallError"`.
- Tools go to the model in key order (section 3), where Node keeps insertion order. The list of the tools in a `NoSuchToolError` message is sorted the same way.
- Bouy does not support Zod or other Standard Schema input schemas, `toModelOutput`, a tool that streams its output, `system` messages in `messages`, the `on...` callbacks, `prepareStep`, `activeTools`, `abortSignal`, `timeout`, `providerOptions`, or `output`. A `retry-after` header that holds a date counts as absent. The `user-agent` header names the runtime `bouy`.

The fake server, `runtime/test/bouy_fake_openai.erl`, serves the tests. `erl -noshell -pa <dir> -eval 'bouy_fake_openai:main()' -extra stdin` prints its port on the first line of stdout and serves until its stdin closes, which `crates/bouy-cli/tests/ai.rs` uses. With `-extra <os pid>`, which `scripts/freeze-expectations.sh` uses, it serves until that process ends. EUnit starts it in the test VM with `start/0`. The model name picks the answer: `fake-500` gets HTTP 500, a name that ends in `echo` gets the request path, body, and headers back as text, `fake-length` gets the finish reason `length`, and another name gets a scripted answer. A prompt that holds `CALLS <json>` scripts the tool calls of each step. The key `sk-fake-key` is the only valid one, and another key gets HTTP 401.

## 17. Reference semantics

`--semantics reference` selects the JavaScript engine of [ADR 0003](../adr/0003-run-typescript-on-beam.md). Each actor is one realm: one BEAM process with a heap of objects in its process dictionary, a promise job queue, and the intrinsics of section 17.6. Sections 2 to 16 describe `--semantics value`. This section describes `--semantics reference`, and it replaces them when Phase 3 of the ADR ends.

### 17.1 Values

Every JavaScript value has exactly one Erlang term. So `=:=` decides SameValue, and any value can be a key of an Erlang map.

| JavaScript  | Erlang term                                                                                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `undefined` | `undefined`                                                                                                                                                                                      |
| `null`      | `null`                                                                                                                                                                                           |
| boolean     | `true`, `false`                                                                                                                                                                                  |
| number      | an integer `I` with `abs(I) =< 2^53`, for every integral value in that range; a float for any other finite value, and `-0.0` for -0; the atoms `'NaN'`, `'Infinity'`, and `'-Infinity'`          |
| string      | a binary when every UTF-16 code unit is at most `16#FF`, one byte for each unit; else `{'$u16', Binary}`, two bytes for each unit, big-endian                                                    |
| BigInt      | `{'$bigint', Integer}`                                                                                                                                                                           |
| symbol      | `{'$sym', Tag, Description}`: `Tag` is a unique integer for `Symbol()`, `registered` for `Symbol.for(Key)`, whose description is the key, or the atom of a well-known symbol, such as `iterator` |
| object      | `{'$o', Id}`: `Id` is a positive integer, or the atom of an intrinsic, such as `'Object.prototype'`                                                                                              |
| function    | `{'$f', Id, Fun}`, with `Fun` of arity 2, `fun(This, Args)`. `Id` is an integer, `{builtin, Name}` for a builtin, or `{fn, Module, Name}` for a module-level function declaration                |
| actor ref   | `{'$actor', Pid}`                                                                                                                                                                                |

A heap cell, `{'$c', Id}`, holds a variable that a closure writes. It is never a JavaScript value.

**Numbers.** JavaScript numbers are doubles. JSC keeps a double that is an exact int32 as an int32, and only other values as doubles (`JSValue::JSValue(double)` in WebKit's `Source/JavaScriptCore/runtime/JSCJSValueInlines.h`). V8 keeps small integers as Smis. Bouy follows the same rule with a wider range. A BEAM small integer is an immediate term of 60 bits, and a float is a boxed term on the process heap, so integers are the fast path. Every integer with `abs(I) =< 2^53` is exactly a double, so the integer form never changes a result. BEAM floats cannot hold NaN or an infinity, so those values are atoms.

`bouy_ref_number:canonical/1` turns any Erlang number into this form, and every operation returns it:

- An integer result outside the range becomes the nearest double. BEAM converts a big integer to a correctly rounded double, so `2^53 + 1` is `2^53`. A result past the largest double is an infinity.
- A float result that is integral and in the range becomes an integer. So `0.5 + 0.5` is `1`.
- A product, quotient, or remainder that is zero has the sign that IEEE 754 gives it, such as `0 * -5` and `-5 % 5`, which are `-0.0`.
- A float operation that overflows raises `badarith` in Erlang, and the result is the infinity of its sign.
- The bitwise operators convert with ToInt32 or ToUint32 and return integers.

`===` on two numbers is `==` in Erlang, so `0 === -0` holds, and `'NaN'` is never equal to itself. SameValueZero, the key equality of `Map`, `Set`, and `includes`, maps `-0.0` to `0` and then compares terms. `bouy_ref_number:to_string/1` prints the shortest digits that read back to the same double, as `Number.prototype.toString` does.

**Strings.** A JavaScript string is a sequence of UTF-16 code units, and a code unit can be a lone surrogate. JSC stores a string in an 8-bit (Latin-1) or a 16-bit buffer (`is8Bit()` in WebKit's `Source/WTF/wtf/text/StringImpl.h`), and Bun uses these strings. V8 has one-byte and two-byte strings. Bouy uses the same two forms, and a string with every unit at most `16#FF` always takes the one-byte form:

- `length` is `byte_size/1`, or half of it, and an index is a binary match, so both take constant time.
- A lone surrogate is a unit like any other.
- ASCII text has the same bytes in Latin-1 and in UTF-8. So the binary literals of the runtime, such as `<<"length">>`, are strings of the engine as they are.
- Two strings are equal exactly when their terms are equal.

Concatenation appends binaries; BEAM appends in place when the left binary is the newest one, so the engine has no ropes. Slicing returns a sub-binary, and the slice of a two-byte string becomes one-byte when it can. The module `bouy_ref_string` holds these operations.

Text crosses the boundary of the engine in two functions. `bouy_ref_string:from_utf8/1` reads UTF-8 and replaces each byte that does not decode with U+FFFD. `bouy_ref_string:to_utf8/1` writes UTF-8 and replaces each lone surrogate with U+FFFD, as Node does when it writes to a stream. Console output, JSON text, the dates and number text of the value core, and the host use these functions. `JSON.stringify` writes a lone surrogate as a `\uXXXX` escape, so its output holds no lone surrogate. The compiler writes each string literal in the engine form (`Expr::JsString`). It reads a lone surrogate from the escape that oxc uses for it.

**BigInt.** An Erlang integer is a number in this form, so a BigInt needs a tag of its own. `{'$bigint', I}` holds the value as an Erlang integer of any size, and `bouy_ref_bigint` holds its operations. Erlang's bitwise operators treat integers as infinite two's complement, as BigInt does. A result past 2^30 bits is a `RangeError`, as in V8. The compiler writes a BigInt literal as this tuple.

**Primitive wrappers.** `new Number(1)`, `Object("s")`, and the other wrappers are objects of the classes `number`, `string`, `boolean`, `bigint`, and `symbol`, with the primitive in their slots. `bouy_ref:to_object/1` makes them, and each prototype method unwraps them (thisNumberValue and the others). A String object holds its code units as read-only index properties and its `length`. A property read on a primitive looks up the prototype with the primitive as the receiver of a getter.

### 17.2 Objects

The heap entry of an object is the record `{Class, Proto, Props, Keys, Attrs, Slots}` under its integer id in the process dictionary:

- `Class` is the kind of the object: `object`, `array`, `function`, `error`, `map`, `set`, `weakmap`, `weakset`, `promise`, `generator`, `list_iterator`, `array_iterator`, `map_iterator`, `set_iterator`, `string_iterator`, `date`, `arguments`, `raw_json`, a primitive wrapper (`number`, `string`, `boolean`, `bigint`, `symbol`), or a class of binary data (`array_buffer`, `shared_array_buffer`, `typed_array`, `data_view`).
- `Proto` is `null` or an object or function value.
- `Props` maps each key to a value, or to `{'$accessor', Get, Set}`.
- `Keys` holds the string and symbol keys, newest first.
- `Attrs` maps a key to its attribute bits (writable 1, enumerable 2, configurable 4) when they are not all set, and holds `'$frozen'` or `'$noext'` for a frozen or a non-extensible object.
- `Slots` holds the internal slots of the class.

An intrinsic is a static record in `persistent_term` that every realm reads. A realm copies the record into its heap when it first writes to the intrinsic. The collector, `bouy_heap:gc/1`, marks and sweeps between jobs, when the stack is empty.

V8 and JSC share one hidden class (a Map in V8, a Structure in JSC) among objects with the same keys, and inline caches remember where a key is. Bouy keeps a map for each object. Shapes and inline caches are Phase 5 of ADR 0003.

### 17.3 Arrays

An array has the class `array` and the slots `{Length, Elements}`. `Elements` maps each index to its value or to `{'$accessor', Get, Set}`, and a missing index is a hole; an array literal with elisions makes holes. `length` is in the slots, not in `Props`, and `Attrs` holds its bits only after a program defines it: it is writable, not enumerable, and not configurable, and a write converts the value with ToUint32 (ArraySetLength). `push` reads and writes the record once for any number of items while neither intrinsic prototype holds an index, so no setter on the chain can see the new elements. The methods of `Array.prototype` follow their algorithms over any object, with HasProperty for holes and ArraySpeciesCreate for their results. `Array.prototype` is itself an array. V8 and JSC keep packed arrays of small integers, doubles, or values in a contiguous store, and holey or sparse arrays in other stores. A contiguous store for dense arrays is future work.

**Map and Set.** The slots of a Map or a Set are `{Index, Order}`. `Index` maps each key, with -0 as 0, to `{Seq, Value}` for a Map and to `Seq` for a Set, where `Seq` counts insertions. `Order` is `{Next, Tree}`, a `gb_trees` from each live `Seq` to its key, so an iterator or `forEach` that remembers its last `Seq` sees the entries that a callback adds and skips the ones it deletes.

**Binary data.** BEAM has no mutable byte array, so the bytes of an `ArrayBuffer` live in an `atomics` array of unsigned 64-bit words, little-endian, off the process heap. Its slots are `{Data, ByteLength, MaxByteLength}`, where `Data` is `detached` after `transfer` and `MaxByteLength` is `none` for a fixed length. A typed array's slots are `{Kind, Buffer, ByteOffset, Length}`, with `Length` `auto` when it tracks a resizable buffer. `bouy_heap` hands each numeric key of a typed array (an index or another canonical numeric string) to `bouy_ref_typed_array`, as the integer-indexed exotic object requires. A buffer holds at most 1 GiB.

**Dates.** A date object holds its time value, an integer or `'NaN'`, in its slots. `bouy_ref_tz` reads the TZif data of the zone in `TZ`, or of `/etc/localtime`, so local time has the zone's historic offsets, and the POSIX rule of the file's footer gives the offsets after its last transition. As V8 does, `toString` names the zone's standard or daylight time, and outside 1970 to 2038 it decides daylight time in an equivalent year.

### 17.4 Functions

A function value carries its Erlang fun, so a call needs no heap read. A function gets a heap record only when it needs one: an arrow function or a method has none until a program writes a property to it. A function expression or a nested function declaration gets a record with its `name`, `length`, and `prototype`, and its slots hold `kind => normal`. A class holds `kind => class`, its parent, and the fun of its `[[Construct]]`. A builtin is the same term in every realm, so its identity holds across realms.

### 17.5 Property keys

A property key is one of these terms:

- an array index, `0 =< K =< 2^32 - 2`, as an integer;
- any other string, as a string of section 17.1;
- a symbol;
- a private name, `{'#', ClassName, Name}`, which is never an own key that reflection returns.

ToPropertyKey turns a canonical numeric string such as `"7"` into the integer, and a number into its string, so `o[7]` and `o["7"]` are one key. `bouy_heap:own_keys/1` returns the keys in the order of OrdinaryOwnPropertyKeys: array indexes in ascending order, then string keys in the order of their creation, then symbols in the order of their creation.

### 17.6 Modules

The compiler lowers in `crates/bouy-compiler/src/reference/`, one file for each area: `context` (the lowering state), `module`, `function`, `class`, `suspend` (`await` and `yield`), `stmt`, `loops`, `exception` (`try`), `expr`, `variable`, `member`, `call`, `literal`, `pattern`, and `analyze`.

The runtime has these modules:

| Module              | Role                                                                                                                                                                                                                                                                                         |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bouy_ref`          | The operations that compiled code calls: properties, calls, classes, operators, equality, and conversions                                                                                                                                                                                    |
| `bouy_heap`         | The heap: records, properties, descriptors, prototypes, own keys, cells, the collector, and the structured clone                                                                                                                                                                             |
| `bouy_jobs`         | The job queue, promises, timers, and actors                                                                                                                                                                                                                                                  |
| `bouy_ref_realm`    | Installs the intrinsics of every family, and holds the global object and the global functions                                                                                                                                                                                                |
| `bouy_ref_<family>` | One family of built-ins each: `object`, `function`, `boolean`, `symbol`, `error`, `number`, `math`, `bigint`, `string`, `regexp`, `array`, `buffer` (ArrayBuffer, SharedArrayBuffer, DataView), `typed_array`, `atomics`, `iterator`, `collection`, `promise`, `json`, `date`, and `console` |
| `bouy_ref_tz`       | The system time zone of the Date family: offsets from the TZif data of the zone                                                                                                                                                                                                              |

A family exports `intrinsics/0`, its static records as `[{Id, Record}]`, and `globals/0`, its global bindings as `[{Name, Value}]`. An entry of a record is `{Key, Value}`, writable and configurable, or `{Key, Value, Bits}` with the attribute bits of section 17.2. A method named `{Name, Length}` in `?METHODS` gets the `name` and `length` properties of a builtin function, and `bouy_ref_realm:function/4` makes any other builtin with them. The global object holds every global binding as a property, and a global read goes through it once the realm writes to it. Its builtin methods call its `method(Owner, Name, This, Args)`, and a constructor called without `new` calls its `call_constructor(Name, This, Args)`. `bouy_ref_realm:families/0` lists the families. `runtime/src/bouy_ref.hrl` holds the macros that the modules share, such as `?IS_STRING/1` and `?IS_NUMBER/1`.

### 17.7 Tests

- `tests/reference/*.ts`: programs whose output must equal the output that Node recorded (section 15). `number-representation.ts` and `string-representation.ts` check the forms of section 17.1.
- `runtime/test/bouy_ref_number_tests.erl` and `bouy_ref_string_tests.erl`: the canonical forms, the arithmetic edge cases, the string boundaries, the exact number formatting, and BigInt. `bouy_ref_buffer_tests.erl` checks the element encodings and the byte storage, and `bouy_ref_tz_tests.erl` the POSIX rules, the daylight saving gaps and overlaps, and `Date.parse`.
- `scripts/test262-dev.sh <path>...`: the development runner for test262. It fetches tc39/test262 at the commit that the test harness pins into `~/.cache/bouy/test262` and builds `crates/bouy-cli/src/bin/test262-dev.rs`. The runner writes `"use strict";`, a `print` function for the host, a `$262` with `global`, `gc`, and a `detachArrayBuffer` that calls `transfer`, `assert.js`, `sta.js`, `doneprintHandle.js` for an `async` test, and the `includes` of the frontmatter before each test, and compiles the program with `--semantics reference`. A `raw` test runs as it is, and a `module` test is a `.mjs` file. Then one VM runs the compiled tests with `runtime/test/bouy_test262.erl`, each in a realm process of its own with its stdout and stderr captured. Such a realm sets `'$bouy_exit'` and `'$bouy_stderr'` in its process dictionary, so `bouy_ref:exit_program/1` ends the realm instead of the VM and `bouy_ref:stderr/0` names the capture. A `negative` test passes when its error happens in its phase: a `BOUY200` diagnostic for `parse`, and an uncaught error of its type for `runtime`. The engine compiles every file as strict code, so the runner skips `noStrict` tests. It prints each failure with its first error line, and then a table per directory. `--jobs`, `--timeout-ms` (10,000 by default), and `--failures <file>` change the run. `--jobs` defaults to half the cores, at most 8. The VM runs `bouy_guard` with a `BOUY_MAX_MEMORY` of 1 GB plus 256 MB for each job, and each realm process has a `max_heap_size` of 256 MB that counts its large binaries. When the VM stops, the runner starts a new VM for the tests that did not start, as long as each VM starts a test. `docs/design/engine-progress.md` records the counts of each run over `test/language` and `test/built-ins`.
