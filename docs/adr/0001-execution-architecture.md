# ADR 0001: Execution architecture

## 1. Status and context

**Status:** Accepted, 2026-10-16.

Bouy is a TypeScript compiler and runtime for AI agents, with actors as its execution primitive. Its model is the BEAM (the Erlang virtual machine): lightweight processes, fair scheduling, fault isolation, message passing, and supervision trees. TypeScript tooling and npm packages such as zod and the Vercel AI SDK must stay compatible.

Constraints:

- A small team must ship a working vertical slice now.
- Tests must prove npm compatibility, and each claim names the package, version, and test ([AGENTS.md](../../AGENTS.md)).

Facts that drive the decision:

1. An ECMAScript job always finishes before the next starts ([ECMAScript jobs](https://tc39.es/ecma262/multipage/executable-code-and-execution-contexts.html)), and no host can preempt one actor among many in one isolate ([js-engines-and-isolates §9](../research/js-engines-and-isolates.md)). Fairness there needs yield points that the Bouy compiler inserts.
2. A Bouy actor holds 14.7 KiB of V8 heap and takes 21.9 µs to spawn on Node 25.9.0, and 15.4 KiB and 18.3 µs on Bun 1.3.11 ([benchmarks](../benchmarks.md#spawn)). A hand-written actor object needs 128 to 184 bytes, and Bouy's runtime state makes up the rest (same document, [measurements-node E1](../research/measurements-node.md)). An idle worker thread adds 6.29 MiB of resident memory on the Homebrew Node build and 7.96 MiB on the official build. A forked Node process uses 46.8 MiB (E1, [js-engines-and-isolates §3.1](../research/js-engines-and-isolates.md)).
3. Actors in one isolate have one heap, one thread, and one copy of package state. One actor's prototype pollution broke `z.object()` in the other actors, and heap exhaustion aborted the process ([js-engines-and-isolates §1.5, §8.1](../research/js-engines-and-isolates.md)).
4. zod 4.6.7 passed on every engine in the rust-and-wasm probes. ai 7.0.142 failed wherever `TransformStream` or `Intl` was missing ([rust-and-wasm-runtimes §4.3](../research/rust-and-wasm-runtimes.md)).

Evidence: `bench/` and the two `measurements-*` notes keep their scripts in the repository, and validation item 10 moves the others into `bench/evidence/`. Other jobs loaded the machine during all measurements (load average 7.6 to 42.8 on 18 cores). Timings are likely upper bounds, and load can move a ratio of two timings either way. Validation item 10 repeats the measurements on an idle machine. Node numbers from `bench/` and from E1 to E6 come from the Homebrew build of Node 25.9.0, which has no startup snapshot, and the engines track used the official build. Numbers marked "Linux VM" ran in Docker on OrbStack, which moved Node timings by factors of 0.78 to 1.43 ([measurements-beam-quickjs](../research/measurements-beam-quickjs.md)).

## 2. Options

**A. TypeScript to BEAM bytecode.** Each actor is a BEAM process with its own heap, preempted after 4,000 reductions. BEAM terms are immutable, so JavaScript objects need an emulated heap with its own collector. Bouy would rebuild JavaScript semantics and the Web and Node APIs, and Node-API addons cannot load ([beam-and-otp §2.1](../research/beam-and-otp.md)).

**B. TypeScript to an intermediate representation on a Rust runtime.** A Tokio host gives each actor its own QuickJS-ng runtime on a coroutine, and the engine's interrupt callback suspends the coroutine. The host copies messages between heaps and must supply Web and Node APIs ([rust-and-wasm-runtimes §5.3](../research/rust-and-wasm-runtimes.md)).

**C. JavaScript on Node or Bun, many actors per isolate.** The compiler lowers user TypeScript and inserts preemption points. npm packages load unchanged. Actors are objects with mailboxes in one isolate, and the runtime copies every message ([npm-compatibility.md](../npm-compatibility.md)).

**D1. Node host with worker-thread schedulers.** A pool of worker threads hosts C's actors and schedules them as C does. Each worker has its own isolate, heap, event loop, and package copies, and it is the failure domain ([js-engines-and-isolates §3](../research/js-engines-and-isolates.md)).

**D2. Rust host with V8 isolates as schedulers.** A Rust host keeps D1's layout. It controls heap-limit callbacks and CPU-time timers, and isolate groups once a rusty_v8 release binds them. It must supply Node APIs ([js-engines-and-isolates §1, §6](../research/js-engines-and-isolates.md)).

**D3. BEAM host for JavaScript.** Each actor is a supervised Erlang/OTP process that owns JavaScript state. D3n keeps it in a QuickJS-ng context behind native implemented functions (NIFs), with polyfilled Web APIs, as QuickBEAM does. D3p keeps it in a Node process behind an Erlang port, where npm packages load unchanged. JavaScript yields only between jobs ([beam-and-otp §3](../research/beam-and-otp.md)).

**D4. WebAssembly (Wasm) components as processes.** Wasmtime hosts one component instance per actor, with JavaScript compiled by StarlingMonkey or Javy. Each instance has its own linear memory, and fuel or epoch checks preempt any loop. npm support depends on the engine's Web APIs ([rust-and-wasm-runtimes §3, §4](../research/rust-and-wasm-runtimes.md)).

**TypeScript and npm compatibility.** In `e2e/npm-equivalence.test.ts`, zod 4.6.7, ai 7.0.142, and @ai-sdk/openai 4.0.95 print byte-identical reports in plain Node and in Bouy actors, on Node 25.9.0 and Bun 1.3.11. D3p uses real Node. D1 needs Node-API or context-aware addons and a loader in each worker ([js-engines-and-isolates §3.5, §3.7](../research/js-engines-and-isolates.md)). B and D3n need rebuilt Web APIs, and QuickBEAM hung on a `pull()` stream ([beam-and-otp §3.4](../research/beam-and-otp.md)). D2 needs a Node layer like Deno's, which passes "over 75%" of Node's tests ([Deno](https://docs.deno.com/runtime/fundamentals/node/)). D4 passed the ai probe only after a regex rewrite, because StarlingMonkey lacks `Intl` ([rust-and-wasm-runtimes §4.1](../research/rust-and-wasm-runtimes.md)). The only JavaScript interpreter found on the BEAM failed zod (A, [beam-and-otp §2.4](../research/beam-and-otp.md)).

**Runtime isolation and fault tolerance.** A and D4 give each actor a private heap and a kill that frees it: `max_heap_size` in OTP ([erlang](https://www.erlang.org/doc/apps/erts/erlang.html)), traps and epochs in Wasmtime ([rust-and-wasm-runtimes §8](../research/rust-and-wasm-runtimes.md)). The BEAM survived a port program's segfault (D3p), but a NIF segfault ended the whole BEAM ([erl_nif](https://www.erlang.org/doc/apps/erts/erl_nif.html), [beam-and-otp §1.4](../research/beam-and-otp.md)). An engine memory bug ends B's process, and a V8 crash ends D2's. Gap 1 (below) also defeated termination on rusty_v8, so B and D2 both get 3, and D2 drops the engines track's 4 ([js-engines-and-isolates §1.4, §8.2](../research/js-engines-and-isolates.md)). D2 can give each isolate its own isolate group once a rusty_v8 release includes [PR #2060](https://github.com/denoland/rusty_v8/pull/2060), which merged on 2026-09-02 and is unreleased on 2026-10-16. D1 contains heap exhaustion per worker, except in Gap 1. There, TurboFan-optimized loops that call no function and allocate fixed-length arrays ignored termination, and with it the heap limit, on V8 13.6 to 15.0 ([js-engines-and-isolates §1.4, §1.5](../research/js-engines-and-isolates.md)). C restarts a faulted actor, but all its actors live in one heap, thread, and module graph. A throw in a listener on a shared emitter restarts the actor that called `emit()`, not the actor that registered the listener ([measurements-node E6](../research/measurements-node.md)).

**Scheduling fairness.** A preempts after 4,000 reductions ([erl_vm.h](https://github.com/erlang/otp/blob/master/erts/emulator/beam/erl_vm.h)). D4 checks epochs (up to 42% extra time) or fuel (up to 101%) at loop back edges and function entries ([rust-and-wasm-runtimes §3.2](../research/rust-and-wasm-runtimes.md)). B's prototype gave spinning actors 84 to 93 µs slices, but `JSON.parse` has no poll site (same note, §5.3). D2's host adds interrupts and CPU-time budgets. Inside an isolate, C, D1, and D2 depend on compiler yields. In [the fairness benchmark](../../bench/fairness/results/fairness-2026-10-16-m5pro.json), a ping was due every 50 ms of a 1,000 ms loop, and the median worst ping was 3.41 to 4.34 ms under Bouy. Plain Node gave 1,003.4 ms. The worst single Bouy run reached 171.8 ms, under the 250 ms bound in `e2e/fairness.test.ts`. The fairness suite in `bench/` sends one ping per 1 ms slot for 2,000 ms. There, compiled pings had a p99 of 6.68 ms and a maximum of 8.28 ms on Node, and 6.89 ms and 11.0 ms on Bun ([benchmarks](../benchmarks.md#fairness)). Package code has no yield points, so C gets 2. D1 and D3p confine a hog to one worker or process. A QuickBEAM context waited 1,898 ms behind a busy context on its thread ([beam-and-otp §3.2](../research/beam-and-otp.md)).

**Startup time and memory per actor.** A Bouy actor holds 14.7 KiB of V8 heap and takes 21.9 µs to spawn on Node, and 15.4 KiB and 18.3 µs on Bun ([benchmarks](../benchmarks.md#spawn)). That state includes an Effect fiber, a `Queue` mailbox, two `Deferred`s, an exit promise, and an `AbortController` ([benchmarks](../benchmarks.md#what-the-numbers-show)). A hand-written actor object needs only 128 to 184 bytes, which is the floor for C (same document, [measurements-node E1](../research/measurements-node.md)). An idle BEAM process uses 2,632 bytes and spawns in 1.2 to 1.5 µs (Linux VM, [measurements-beam-quickjs](../research/measurements-beam-quickjs.md)). A Bouy actor therefore uses 5.7 times that memory and 15 to 18 times that spawn time. A scores 3 only because its per-actor package state is unmeasured, so C's lead over A is unverified. C gets 4, because every other option that runs JavaScript in an engine costs more per actor. B's QuickJS-ng runtime costs 174 to 190 KiB per actor without host APIs, a setup that fails the ai probe, and B with Web APIs is unmeasured. D3n costs 737 to 739 KiB per context with browser APIs (Linux VM), and D4 about 1.6 MiB (1,669 to 1,688 KiB) per instance ([rust-and-wasm-runtimes §4.1, §4.3, §5.2, §5.3](../research/rust-and-wasm-runtimes.md), [beam-and-otp §3.2](../research/beam-and-otp.md)). D3p costs about 40 MiB per Node process (Linux VM, same note, §3.3). D1 and D2 run C's actors and add a cost per scheduler, so they get 3. A worker with the agent packages costs 23.7 MiB and 132 ms on the official Node build, and a bare V8 isolate 1,080 KiB ([js-engines-and-isolates §1.2, §3.1](../research/js-engines-and-isolates.md)).

**Message throughput and latency.** A Bouy call to a sync method had a p50 of 2.00 µs on Node and 1.17 µs on Bun ([benchmarks](../benchmarks.md#request-reply)). With 64 calls in flight, one Bouy actor answered 407 thousand calls per second on Node. These calls pass numbers, and an object argument adds a Schema copy, 2.16 µs for a 77-byte record ([benchmarks](../benchmarks.md#messages)). A hand-written mailbox with no copy and no Effect fiber sets the floor: a 0.167 µs p50, and 14.7 million round trips per second with 64 lanes ([measurements-node E2](../research/measurements-node.md)). A raw BEAM round trip had a p50 of 0.458 µs, and `gen_server:call` 0.750 µs (Linux VM, [measurements-beam-quickjs](../research/measurements-beam-quickjs.md)). A Bouy call therefore takes 2.7 to 4.4 times as long, a gap larger than the VM's effect on timings. A must add copies between emulated heaps, which no track measured, so A and C both get 3. On Node, one worker echo answered 1.25 times as many calls per second as one Bouy actor, so C's limit is its call path, not its single thread. D1 runs the same call path in each worker and also gets 3. A round trip between the main thread and a worker took 8.5 to 13.6 µs with a number and 27.3 µs with a 64-byte object (E2, [benchmarks](../benchmarks.md#request-reply), [js-engines-and-isolates §3.2](../research/js-engines-and-isolates.md)). No track measured a round trip between two workers. B's Rust-to-JS calls took 36 to 41 ns, and a Tokio round trip took 109 to 126 ns on a multi-thread runtime, so B keeps its track's 4 ([rust-and-wasm-runtimes §1.4, §5.2](../research/rust-and-wasm-runtimes.md)). B, D2, and D4 also copy between heaps, and no track measured realistic payloads. Median calls took 13 to 36 µs into D3n and 4.5 to 6.7 µs through a D3p port (Linux VM, [beam-and-otp §3.2, §3.3](../research/beam-and-otp.md)).

**I/O and streaming performance.** C, D1, and D3p use Node's native asynchronous I/O, and all workers draw on one libuv threadpool, 4 threads by default ([libuv](https://docs.libuv.org/en/v1.x/threadpool.html)). Bouy's stream layer adds a measured cost. An `async *` actor method delivered 0.977 million items per second on Node and 1.56 million on Bun, which is 12.8 and 9.03 times slower than a plain async generator ([benchmarks](../benchmarks.md#streaming)). For 1,000 agents that await timers, Bouy added 7.83 µs per call on Node ([benchmarks](../benchmarks.md#fan-out)). Both suites run in one process with no network I/O. C and D1 keep 4, because their I/O stays native and Bouy's per-item rate falls inside the 0.34 to 1.16 million messages per second that a Node port passed (D3p, Linux VM, [beam-and-otp §3.3](../research/beam-and-otp.md)). No track measured streaming for the other options. B uses Tokio for I/O, but QuickJS-ng took 68.9 ms on a JSON workload that took V8 26.1 ms ([rust-and-wasm-runtimes §5.6](../research/rust-and-wasm-runtimes.md)). D2 must build its I/O layer, and D3n and D4 copy every byte across a boundary. A's emulated-heap mutation was 13.4 to 16.3 times slower than V8 ([beam-and-otp §2.2](../research/beam-and-otp.md)).

**Implementation complexity.** C needs a compiler pass and a runtime library, and the slice exists. D1 adds a worker pool, placement, cross-worker copies, and a watchdog on stable Node APIs. It also needs a ref wire format, cancellation and stream transport between workers, and per-worker supervision. `packages/bouy/test/threads.test.ts` covers one actor alone in a worker, and today's thread actors lack refs, cancellation, and streams (section 4). D1 therefore takes the actor-models track's 2 over the engines track's 3. D3 needs two runtimes and two toolchains. B and D4 need a runtime with Web APIs, and ComponentizeJS calls itself experimental ([ComponentizeJS](https://github.com/bytecodealliance/ComponentizeJS)). A is a JavaScript engine written as a compiler. D2 must follow each V8 upgrade. isolated-vm, a V8 embedder, lists the major versions that support each Node major (6.x or 5.x for Node 24, 7.x for Node 26), and 7.0.1 did not build on Node 25.9.0, which its table omits ([isolated-vm](https://github.com/laverdet/isolated-vm), [js-engines-and-isolates §4](../research/js-engines-and-isolates.md)).

**Debuggability and tooling.** C keeps one inspector target, CPU profiles, and heap snapshots, but lacks actor views such as mailbox depth. D1 has an inspector target per worker, and Temporal's TypeScript SDK ignores its thread-pool size in debug mode ([Temporal](https://typescript.temporal.io/api/interfaces/worker.WorkerOptions)). D3p pairs the Node inspector with BEAM tools. No track found a JavaScript debugger for the BEAM (A) or a maintained QuickJS-ng debugger (B, D3n). D2 must wire the inspector itself, and StarlingMonkey's debugger (D4) is experimental ([debugger README](https://github.com/bytecodealliance/StarlingMonkey/tree/main/debugger/vscode-dap-extension)).

**Long-term extensibility.** D2 controls startup snapshots, schedulers, and heap and CPU limits, and isolate groups once rusty_v8 releases them ([js-engines-and-isolates §1.3 to §1.6](../research/js-engines-and-isolates.md)). Cloudflare Workers puts one isolate in each isolate group's sandbox ([Safe in the sandbox](https://blog.cloudflare.com/safe-in-the-sandbox-security-hardening-for-cloudflare-workers/)). It limits memory per isolate and CPU time per request ([Workers limits](https://developers.cloudflare.com/workers/platform/limits/)). D1 already copies messages across an isolate boundary, which distribution needs. B can swap engines. D4 gains WebAssembly System Interface (WASI) 0.3 async once JavaScript toolchains adopt it. WASI 0.3.0 shipped on 2026-06-11 ([WASI 0.3](https://wasi.dev/releases/wasi-p3)), but ComponentizeJS imports stay synchronous "pending component-model-level async support" ([ComponentizeJS](https://github.com/bytecodealliance/ComponentizeJS)). C stays on one core. Its actor code can move into D1 once refs, cancellation, and streams cross workers (section 5). D3 keeps two runtimes, and A makes each new ECMAScript feature Bouy's job.

## 4. Decision

Bouy adopts C now and grows into D1. The decision rests on compatibility, where C and D3p alone score 5. D3p with one Node process per actor costs about 40 MiB per actor (Linux VM). A pool of Node processes would hold many actors per process again, which is C inside a BEAM host. That pool adds BEAM supervision at the cost of a second runtime and toolchain, and a Node parent gives Bouy the same process backstop (Target, below). C also leads on implementation complexity and debuggability. On memory per actor, C leads every other option that runs JavaScript in an engine, but a Bouy actor uses 5.7 times the memory of an idle BEAM process. D1 raises C's two weak scores, isolation and fairness, once refs, cancellation, and streams cross workers. A, D2, and D4 score 2 or less on compatibility, which blocks the slice. B and D3n must rebuild Web APIs before the AI SDK passes its tests.

Now:

- Node is the primary host on its long-term support (LTS) lines: Node 24 now, and Node 26 once it becomes LTS on 2026-10-28. The repository already declares `node >=24`. Node 25 reached end of life on 2026-06-01 ([Node release schedule](https://raw.githubusercontent.com/nodejs/Release/main/schedule.json)). Every Node measurement in this ADR ran on Node 25.9.0 with V8 14.1, so validation item 11 repeats the key checks on Node 24 and 26.
- Bun 1.3.11 is a second host with the gaps below. Like Deno 2.9.7, it did not stop a spinning worker, and Bun ignores worker heap limits ([js-engines-and-isolates §6, §7](../research/js-engines-and-isolates.md), [Bun](https://bun.com/docs/runtime/nodejs-compat)). Bun 1.4.3, released on 2026-10-10, stopped a spinning worker in the Linux VM (§7, [release](https://github.com/oven-sh/bun/releases/tag/bun-v1.4.3)). Deno is out, because no Bouy test runs on it.
- The Rust compiler lowers user modules only. It inserts a preemption point at the top of each loop inside an `async` function (`crates/bouy-compiler/src/lib.rs`).
- Each turn runs inside its actor's `AsyncLocalStorage` context. On Node, a fault from a timer, microtask, promise, `fs` callback, or emitter that the actor itself triggers reaches its supervisor ([measurements-node E6](../research/measurements-node.md)). A listener on an emitter that another actor triggers is the exception: its fault reaches the emitting actor's supervisor.
- An actor spawned with `isolation: "thread"` lives alone in a worker, with a stall watchdog and an optional heap limit. Its worker runs no turn, so compiled loops do not yield there, refs and cancellation do not cross, and streaming methods fail.

Target (D1):

- Worker-thread schedulers host the actors. A supervisor restarts a failed worker, then its actors from their specs.
- A parent process can kill a scheduler process, because Gap 1 loops escape a worker. Native crashes are expected to escape it too, which validation item 1 will verify.
- A host-neutral boundary (spawn, send, receive, link, monitor, exit) lets a D2 or D4 tier host sandboxed tool code later.

For default actors, functions and class instances fail with `NotSendable`, so callbacks cross as actor references. Mutable objects cross as Schema-validated copies. On Node, a rejected floating promise is a defect of its actor. A fault with no owning turn is logged and sets exit status 1, and the process keeps running. A late fault from a stopped or restarted actor takes the same path (`e2e/late-fault.test.ts`). The scheduler yields to the event loop with a macrotask, since microtask-only draining starved timers ([measurements-node E2](../research/measurements-node.md)). In default actors, native modules, Node APIs, and I/O behave as in plain Node, and cancellation reaches code that accepts an `AbortSignal`. One garbage collector serves each isolate, so Bouy cannot limit one actor's heap.

## 5. Consequences

Easy:

- npm packages and Node tooling behave as in plain Node in default actors.
- Every send already copies its message, so actors share no mutable object through a send.

Hard:

- Fairness covers compiled code only, so agents with long synchronous package calls need thread isolation.
- A runaway synchronous call in a default actor hangs every actor. Under `bouy run`, the SIGINT and SIGTERM handlers are JavaScript callbacks, so they cannot run either, and no watchdog covers the main thread ([js-engines-and-isolates §3.8](../research/js-engines-and-isolates.md)).
- Each compiled loop iteration pays for a preemption check. E5 measured 0.57 to 0.91 ns per iteration for a check that decrements a counter, 213% to 332% of a trivial loop body ([measurements-node E5](../research/measurements-node.md)). Five of the seven `bench/suites/` skip the compiler, and the fairness suite does not separate `tick()` from yielding, so the cost of Bouy's own `tick()` is unmeasured ([benchmarks](../benchmarks.md#method)).
- Every send copies object arguments through an Effect Schema decode, which costs 2.64 to 4.54 times `structuredClone` on Node. It takes 2.16 µs for a 77-byte record and 21.1 ms for 813,891 bytes ([benchmarks](../benchmarks.md#messages)). The copy is synchronous, so a large message blocks every actor on the thread.
- A worker hop adds a structured clone and a Schema decode in each direction (`packages/bouy/src/thread/`). `structuredClone` alone costs 22% to 38% of the Schema copy on those payloads.
- A thread actor differs from a default actor: refs arrive as empty objects, cancellation and streams do not cross, and errors keep only their name, message, and stack. Workers lack `process.chdir()` and signal delivery, get a copy of `process.env`, and load only Node-API or context-aware addons ([js-engines-and-isolates §3.1, §3.7](../research/js-engines-and-isolates.md)). D1 must close each difference before actor code moves between placements.
- A fault with no owning turn leaves the process running, although Node warns that resuming after `uncaughtException` is not safe ([js-engines-and-isolates §3.6](../research/js-engines-and-isolates.md)).
- Actors cannot migrate between workers, so placement is final at spawn.

The documentation must state:

- Every "No" and "Unverified" cell in the section 4 table.
- A throw in a listener on an emitter that another actor triggers restarts the emitting actor.
- Today a late fault from a stopped or restarted actor disappears without a log.
- Library errors cross as copies, so `instanceof` checks fail ([npm-compatibility.md](../npm-compatibility.md)).
- A restart discards in-memory state until durability exists.
- ai 7.0.142 ends an aborted stream without throwing, so wrappers must check `signal.aborted` ([actor-models A.4](../research/actor-models.md)).

## 6. Validation

## 7. Revisit triggers

1. `e2e/fairness.test.ts` exceeds its 250 ms worst-ping bound on Node, or a profile shows package code holding the thread longer. Evaluate engine-level preemption (B or D4) for those actors.
2. Heap exhaustion, a Gap 1 loop, or a native addon ends a Bouy process, or a synchronous call hangs one. Build the process backstop first.
3. The load benchmark keeps one core fully busy while actors wait. Ship the D1 scheduler pool.
4. Official Node builds enable pointer compression. Re-measure D1 and D2 scheduler cost ([js-engines-and-isolates §1.3](../research/js-engines-and-isolates.md)).
5. StarlingMonkey closes [issue #45](https://github.com/bytecodealliance/StarlingMonkey/issues/45) (`Intl`), and the ai probe passes unpatched. Re-score D4 as a sandbox tier for model-generated code.
