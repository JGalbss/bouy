# Conformance corpus

Each program in this directory uses only language features and globals: no actors and no imports. Next to each `<name>.ts`, `<name>.stdout` holds what Node printed, and `<name>.status` holds the exit status when it is not 0. `crates/buoy-cli/tests/conformance.rs` runs each program with `buoy run` and asserts that stdout and the exit status equal these files, so the tests never run Node. A program avoids the documented differences of section 3 of `docs/design/beam-runtime.md`. For example, it prints objects with a single key or with keys in sorted order, and it uses integers below 2^53.

To add a program or to change one, run `scripts/freeze-expectations.sh tests/conformance` and commit the new `.stdout` and `.status` files with the program. The script is the only test step that runs Node. It refuses a Node release other than the one in `.node-version`. It runs each program twice, with a fixed time zone, locale, and environment, and it refuses a program whose two runs differ, so a program that depends on time or order cannot enter the corpus. Then run `cargo test -p buoy-cli --test conformance`, or `BUOY_TEST_FILTER=<name> cargo test -p buoy-cli --test conformance` for the programs whose path contains `<name>`. A program without a `.stdout` file fails the test. On a failure, the test prints for each program the exit statuses, the lines that differ (`-` for Node and `+` for Buoy), the stderr of Buoy, and the command that reruns the program.
